# 单电机测试脚本与自动识别 ID

这些脚本用于单电机速度测试：**先只读发现 ID，再初始化、运行指定时间，最后停车并关闭输出**。不填 `--motor-id` 会自动扫描；明确填写时也会先验证该 ID 的只读应答。

本次只做软件验证，没有再次运行实机。此前 DM 节点7、Master ID8 的 +1 rad/s 实测结果，不代表新增脚本或其他电机已通过实机验收。

## 1. 文件与支持范围

所有命令从 `/home/fire/ros2_ws_car/src` 执行。

| 电机/协议 | 脚本 | 默认设备 | 默认速度 | 默认时间 |
| --- | --- | --- | --- | --- |
| 达妙 DM | `tools/run_dm_velocity.py` | `can0` | +1 rad/s | 1 s |
| 脉塔 MT | `tools/run_mt_velocity.py` | `can0` | +0.5 rad/s | 1 s |
| 易优私有 PP | `tools/run_pp_velocity.py` | `canable1` | +0.2 rad/s | 1 s |
| INNFOS ECB 网络执行器 | `tools/run_ecb_velocity.py` | `ecb://auto` | +0.2 rad/s | 1 s |
| CANopen CiA402 | `tools/run_canopen_velocity.py` | `canable0` | +0.1 rad/s | 1 s |

前四种共用 `motor_velocity_common.py`，自动启动当前已安装的 `can_driver_node`，仅注册选中的一台电机。CANopen 脚本直接使用 SocketCAN SDO，仅支持设备声明支持的 **Profile Velocity 模式3**，不启动 ROS 主站，不代替现有 CSV9/IP7 整车控制链。

`motor_discovery.py` 是只读识别模块；`ecb_lookup_readonly.cpp` 是 ECB SDK 只读发现工具，首次扫描会编译到 `/tmp`。入口与公共文件需保留在同一目录，不要只复制一个入口文件到其他位置。

## 2. 准备环境

DM、MT、PP、ECB 的运动入口需要当前驱动安装环境：

```bash
cd /home/fire/ros2_ws_car/src
source /opt/ros/humble/setup.bash
source /tmp/dm-1rad-install/setup.bash
export ROS_DOMAIN_ID=79
export ROS_LOCALHOST_ONLY=1
export ROS_LOG_DIR=/tmp/motor-test-ros-logs
```

`/tmp/dm-1rad-install` 是此前测试的安装目录。如已清理，可重建：

```bash
source /opt/ros/humble/setup.bash
colcon --log-base /tmp/dm-1rad-log build \
  --base-paths robot_safety can_driver \
  --build-base /tmp/dm-1rad-build --install-base /tmp/dm-1rad-install \
  --cmake-args -DBUILD_TESTING=OFF -DCMAKE_BUILD_TYPE=Release
source /tmp/dm-1rad-install/setup.bash
```

也可以 source 自己构建的安装目录，但须包含当前驱动和消息。不要同时运行控制同一电机的旧驱动、整车 bringup 或其他主站。每次测试会生成独立的 ROS 命名空间，避免脚本之间的服务重名，但这不能解决多个程序同时控制同一物理电机的问题。

CAN 接口须已按**电机实际波特率**开启。例如接口关闭且电机实际为1 Mbit/s时：

```bash
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 txqueuelen 1000
sudo ip link set can0 up
ip -details -statistics link show can0
```

替换成实际接口名。脚本不自动更改波特率、不复位 BUS-OFF、不遍历主机波特率，也不改电机 ID。CAN 扫描要求接口为 `UP / ERROR-ACTIVE`；异常状态或错误帧会终止扫描。

## 3. 自动识别 ID 的方法

| 类型 | 只读查询 | 默认节点范围 | 自动得到的附加信息 |
| --- | --- | --- | --- |
| DM | 标准帧0x7FF，读取寄存器10 | 0–15 | 应答帧 ID 即 Master ID；控制模式 |
| MT | `0x140 + 节点号`，读取0x9A状态/错误 | 1–255 | 故障码 |
| PP | 帧ID为节点号，短帧`03 02`读取序列号 | 1–255 | 序列号 |
| ECB | SDK `lookupActuators()` | SDK发现全部可达设备 | 执行器ID与IP |
| CANopen | SDO读取1018:01 Vendor ID | 1–127 | Vendor ID |

CAN 默认每节点等待0.2秒，共遍历2轮；**找到第一台后仍继续扫描指定范围**，以检查多电机情况。无应答不证明节点绝对不存在；慢固件可延长超时。DM 范围与当前驱动支持的4位节点号一致，不支持扫描后直接控制16以上的DM节点。

完整扫描不含额外开销时：DM约6.4秒，MT/PP约102秒，CANopen约51秒。可以缩小范围加快发现。

只扫描，不使能、不运动，不需要 ROS 驱动运行：

```bash
python3 tools/run_dm_velocity.py --device can0 --scan-only
python3 tools/run_mt_velocity.py --device can0 --scan-only
python3 tools/run_pp_velocity.py --device canable1 --scan-only
python3 tools/run_ecb_velocity.py --scan-only
python3 tools/run_canopen_velocity.py --device canable0 --scan-only
```

缩小扫描范围，或提高慢设备的应答等待：

```bash
python3 tools/run_pp_velocity.py --device can0 --scan-start 1 --scan-end 32 --scan-only
python3 tools/run_dm_velocity.py --device can0 --scan-timeout 0.5 --scan-retries 3 --scan-only
```

只有一台符合条件的设备才自动选择；多台会打印列表并退出。指定目标后再次读取确认，例如：

```bash
python3 tools/run_dm_velocity.py --motor-id 7 --master-id 8 --speed 1 --duration 1
python3 tools/run_pp_velocity.py --device can0 --motor-id 0x13 --speed 0.2 --duration 1
```

DM的 `--master-id` 可省略，默认使用真实应答帧的 ID，不会写入电机寄存器。ECB若不同IP使用相同ID，必须同时指定 `--device ecb://IP`。同一CAN总线上的重复节点号可能无法从应答区分，应逐台接入配置；脚本不能保证识别这种地址冲突。

## 4. 修改参数的方法

### 方法一：命令行覆盖

```bash
python3 tools/run_dm_velocity.py --speed -0.5 --duration 3 --device can0
```

表示：自动识别DM节点，以 −0.5 rad/s 运行3秒，然后停车。命令行优先于文件中的默认值。

### 方法二：修改入口顶部的默认值

每个入口都有 `DEFAULT_*`，例如：

```python
DEFAULT_MOTOR_ID = None   # None自动发现；改为7则只验证节点7
DEFAULT_DEVICE = "can0"
DEFAULT_SPEED = 0.5       # rad/s，负数反转
DEFAULT_DURATION = 2.0   # 秒
DEFAULT_DIRECTION = 1    # +1或-1，修正实际安装方向
```

DM还有 `DEFAULT_MASTER_ID = None`，表示自动读取反馈ID。CANopen的 `DEFAULT_VELOCITY_SCALE = None` 必须根据实际型号填写，或通过命令行传入。

### 参数表

| 参数 | 含义与设置方法 |
| --- | --- |
| `--speed` | 目标速度，转动电机单位rad/s；负数反转。rpm转rad/s：`rpm * 2π / 60` |
| `--duration` | 正的运行秒数，不包含扫描、初始化和停车时间 |
| `--device` / `--interface` | SocketCAN接口；ECB用`ecb://auto`或`ecb://实际IP` |
| `--motor-id` | 省略自动发现；前四种支持十进制、`0x`十六进制。CANopen同样支持这两种ID写法 |
| `--master-id` | 仅DM：过滤并确认反馈帧ID，省略自动识别 |
| `--direction` | +1或−1；同时修正命令与反馈方向。负速度与−1方向会再次反向 |
| `--position-scale` | 前四种：位置SI/raw换算；PP支持填写PPR如65536 |
| `--velocity-scale` | 命令速度SI/raw换算；PP可填PPR，其他类型按下表单位设置。CANopen须显式提供，且只接受直接系数 |
| `--speed-limit` | 指令和实际速度绝对值上限；前四种默认2 rad/s，CANopen默认0.2 rad/s；超过即尝试停车 |
| `--stop-tolerance` | 停稳判定的速度绝对值阈值；前四种默认0.05 rad/s，CANopen默认0.02 rad/s |
| `--scan-start` / `--scan-end` | CAN遍历范围，包含两端；指定motor-id时仅查询该ID |
| `--scan-timeout` | 每节点每轮监听时间，默认0.2秒 |
| `--scan-retries` | 完整扫描轮数，默认2 |
| `--discovery-timeout` | ECB SDK发现进程超时，默认30秒 |
| `--feedback-timeout` | 前四种状态话题接收超时，默认0.5秒；不能替代底层硬件反馈有效性 |
| `--startup-timeout` | 前四种等待首组有效反馈，默认5秒 |
| `--sdo-timeout` | CANopen每次SDO应答期限，默认0.5秒 |
| `--allow-sdk-cache` | 仅ECB运动时需要，显式接受第6节中的SDK缓存验证限制 |
| `--scan-only` | 只发现并列出结果，不初始化运动驱动 |
| `--dry-run` | 离线输出配置，不打开CAN、不扫描、不运动；需指定motor-id，DM还需master-id，ECB需固定IP |

各脚本 `--help` 可查看该脚本的实际可用参数。速度、时间、比例和阈值均会校验；无效ID、NaN、超限速度、整数溢出及小于半个原始单位的速度会拒绝运行。

## 5. 各类型示例与单位换算

### DM

```bash
# 自动识别，+1rad/s运行1秒
python3 tools/run_dm_velocity.py --device can0 --speed 1 --duration 1

# 已知节点7，反向0.5rad/s运行2秒，Master ID仍自动识别
python3 tools/run_dm_velocity.py --device can0 --motor-id 7 --speed -0.5 --duration 2
```

DM的position/velocity scale固定为 **0.0001**，与后端定点SI单位一致。不要填16384或65536。量程由驱动读取电机实际PMAX/VMAX/TMAX，不需要脚本预设。初始化会确认速度模式；不保存参数、不写零点。

### MT

```bash
python3 tools/run_mt_velocity.py --device can0 --scan-start 1 --scan-end 32 --speed 0.5 --duration 2
python3 tools/run_mt_velocity.py --device can0 --motor-id 1 --speed -0.5 --duration 1
```

**这里ID填节点号1，不填CAN帧ID 0x141。** 当前后端会自行加0x140；节点1发送0x141、接收0x241。旧脚本和历史配置可能使用不同ID表达方式，不能原样照搬。

按仓库脉塔协议：A2速度指令是 **0.01 deg/s/raw**，反馈是 **1 deg/s/raw**，多圈位置是0.01 deg/raw。因此脚本配置position/velocity scale为 `π/18000`，保证发送正确；打印和超速检查使用 `原始速度 * π/180`。当前驱动发布的MT `joint_velocity` 仍按命令比例换算，脚本已单独处理这个100倍差异，未修改驱动。

### PP

```bash
python3 tools/run_pp_velocity.py --device canable1 --scan-start 1 --scan-end 32 --speed 0.2 --duration 1
python3 tools/run_pp_velocity.py --device canable1 --motor-id 0x13 \
  --position-scale 65536 --velocity-scale 65536 --direction -1 --speed 0.2 --duration 2
```

默认沿用仓库转动PP轴的65536 count/rev配置，即 `2π/65536`。**ID扫描不能确定编码器比例或机械减速比**，需按实际设备核对；速度寄存器也须确认与该比例对应。

夹爪若为直线关节，上层单位是m和m/s，不能使用默认转动轴参数。应按已校准的m/count比例设置两个scale，同时把速度和阈值全部改成m/s。仓库现有夹爪比例为 `1.7807297172304439e-6 m/count`，仅供匹配该传动机构的设备使用。脚本控制台的rad/s标签面向本说明的转动测试，直线轴需按传入比例理解为m/s。

### ECB

```bash
# 先只读发现ID和IP
python3 tools/run_ecb_velocity.py --scan-only

# 发现唯一设备后，接受当前SDK缓存监测限制，+0.2rad/s运行1秒
python3 tools/run_ecb_velocity.py --speed 0.2 --duration 1 --allow-sdk-cache

# 多设备时明确指定；下面IP为示例，请替换成扫描结果
python3 tools/run_ecb_velocity.py --device ecb://192.168.1.30 --motor-id 2 \
  --speed -0.2 --duration 2 --allow-sdk-cache
```

默认位置 `2π/10000 rad/raw`；速度 `2π/600 rad/s/raw`（后端1 raw=0.1 rpm）。如果还存在外部减速传动，按实际输出轴单位换算。

发现需要g++、仓库自带SDK库及SDK LogTool运行权限。工具只调用`lookupActuators()`，不调用旧的 `discover_ecb_and_enable_yaml.sh`，不会自动回填整车YAML或自动选中第一台。若日志提示SDK权限问题，按厂家LogTool设置流程处理，相关文件位于 `can_driver/lib/innfos-cpp-sdk/tools/logtool/linux_x86_64/`。脚本不会自动改权限、网卡IP或执行sudo。固定IP参数是在SDK发现结果上过滤；仍需SDK发现网络可达。

### CANopen CiA402

```bash
# 只读发现节点
python3 tools/run_canopen_velocity.py --device canable0 --scan-only

# 以下只适用于已确认60FF/606C为counts/s、每圈19857408 count的设备
python3 tools/run_canopen_velocity.py --device canable0 --motor-id 1 \
  --velocity-scale 3.1641517901931543e-7 --speed 0.05 --duration 1
```

上例系数为约 `2π/19857408`，须按实际精确比例设置。仓库另有6619136 count/rev的轴，不能共用该系数。节点号和Vendor ID不能证明速度单位，脚本因此不自动填写比例。

流程为：读6041状态字/606C速度 → 检查6502是否声明支持模式3 → 读回并暂存6061原模式 → 目标速度清零 → 设置6060=3并读回 → 向目标节点发送NMT Start → CiA402状态转换 → 周期SDO写60FF并读606C/6041 → 零速、Quick Stop、Disable Voltage → 确认停稳和关闭输出 → 恢复原模式并读回。NMT不广播，不复位节点，不写零点/保存对象；结束后目标节点仍处于NMT Operational，输出已关闭。

若6502不支持模式3、对象不存在或设备拒绝状态转换，会停止，不会自动尝试CSV9/IP7或猜测PDO映射。现有CANopen整车主站必须停止；这个独立SDO测试不验证整车SYNC/PDO控制周期。

## 6. 停车、反馈验证与限制

DM/MT/PP/ECB以50Hz发送速度指令，驱动direct命令超时0.2秒。结束、Ctrl+C、SIGTERM或运行异常时，依次尝试零速、halt、disable、shutdown并退出驱动；其中某一步失败仍继续尝试后续停车步骤。日志和本次单轴配置保留在终端打印的 `/tmp/<类型>-velocity-*` 目录。CANopen直接执行其独立SDO停车流程。

| 类型 | 实际验证的内容 | 限制 |
| --- | --- | --- |
| DM/PP | 新鲜、有效的位置/速度/模式/状态及故障标志；结束时检查速度和失能 | 不等于外部量具校准或失联停车验收 |
| MT | 只读身份/故障应答、新鲜有效的位置和速度、运行故障字段与速度阈值 | 当前后端无独立硬件模式/使能读回；启停服务的软件成功不能证明硬件使能状态 |
| ECB | SDK发现身份；显式接受限制后监测状态话题、SDK缓存速度/使能/故障 | 当前后端未接入完整共享反馈有效性与新鲜度；新话题可能承载旧缓存，不能宣称严格失联检测通过 |
| CANopen | SDO应答、状态字、实际速度、支持模式与模式读回 | 不支持的对象/模式会拒绝；速度比例依赖型号确认，无通用自动推断 |

ECB默认可直接扫描，但缺少 `--allow-sdk-cache` 时会在启动运动驱动前退出。这个开关不会修复底层缓存验证，也不会把缓存标为真实有效。

这些软件停车流程依赖主机、进程和通信继续正常运行。此前读取的DM TIMEOUT=0；断线、强杀进程、主机掉电的自主停车未验证。MT后端初始化还会按现有实现发送300ms通讯中断保护配置；脚本没有新增保存或零点写入。

## 7. 离线检查与排障

不连接硬件，查看将生成的配置：

```bash
python3 tools/run_dm_velocity.py --dry-run --motor-id 7 --master-id 8
python3 tools/run_mt_velocity.py --dry-run --motor-id 1
python3 tools/run_pp_velocity.py --dry-run --motor-id 0x13
python3 tools/run_ecb_velocity.py --dry-run --motor-id 2 --device ecb://192.168.1.30
python3 tools/run_canopen_velocity.py --dry-run --motor-id 1 --velocity-scale 3.1641517901931543e-7
```

执行离线测试：

```bash
python3 -m unittest discover -s tools/test -p test_motor_velocity_tools.py -v
```

无应答时先确认供电、实际接口、实际波特率、H/L、终端电阻及协议类型，再调整扫描范围和应答期限。扫描成功但初始化失败时查看打印的驱动日志；不要通过取消反馈检查来绕过故障。软件检查通过只证明报文/参数处理等逻辑，不代表实机运动通过。
