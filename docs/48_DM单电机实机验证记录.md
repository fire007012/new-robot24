# DM 单电机实机验证记录

日期：2026-11-08。用户接入一个 DM 电机，要求速度模式 +1/−1 rad/s，以及位置正转 90°、反转 90°。本轮通信检查未通过，四段运动均未执行。

## 通信检查

can0 初始 UP、ERROR-ACTIVE，1 Mbit/s，发送队列 1000；error-warning、error-passive、bus-off 均为 0。当前沙箱禁止 CAN 套接字，使用批准的主机访问执行检查。

使用标准帧 0x7FF，数据为小端节点号、0x33、寄存器 10、四字节零，仅查询 DM 控制模式，不发送使能、运动、保存、零点或参数写入。节点 1–32 未收到应答；扩大至 0–255 的扫描中途发送超时，未完成全部节点扫描。随后 can0 为 BUS-OFF，停止进一步发送。未识别到电机型号、节点或真实模式。

最终内核显示 error-warning 702、error-passive 67910、bus-off 248022，收发 errors 字段为 0。计数按工具原样记录，不能据其推断独立故障次数或根因；未复位接口或改波特率。需确认设备供电、CAN H/L、终端及实际波特率后恢复总线。

## 软件边界

当前 `can_driver/src/DamiaoCan.cpp` 仅支持速度模式；`setPosition`、`quickSetPosition` 及非速度模式选择会拒绝请求。不能将现有驱动登记为支持 DM 位置模式。待通信恢复、型号和参数确认后，再确定位置速度模式的适配和验证路径。

没有启动电机驱动节点，没有下发使能或四段运动命令，没有修改电机参数；不能登记速度或位置测试通过。只读探测脚本见 [证据目录](evidence/20261108-dm-single-axis/)。该脚本没有自动 BUS-OFF 恢复，不应在故障总线上继续重复扫描。

## 上电与 USB 重新插拔后复查

用户说明首轮电机未上电，随后已上电。直接 restart 报设备不支持，down/up 后仍 BUS-OFF；用户重新插拔 CAN 卡并配置 1 Mbit/s，接口变为索引 6、ERROR-ACTIVE，全部错误计数清零。

复查节点 1–4 的只读模式查询无应答，紧随检查时 TX/RX 均为零；随后仅追加节点 1 的单帧只读查询并监听错误帧约 2 秒，捕获 3394 个错误帧，未识别出 DM 应答。错误帧示例 `0x2000000c:0030080000000000`、`0x2000004c:000c080000000000`。按本机 linux/can/error.h，协议类型 data[2]=0x08 表示无法发送显性位，后者还标记 BUS-OFF；这是驱动上报的解释，不足以定位具体接线或硬件故障。

最终再次 BUS-OFF，error-warning 560、error-passive 42822、bus-off 156466；TX/RX 均显示 3 帧/24 字节。没有继续扫描或发送使能、运动命令。初始 ERROR-ACTIVE 只证明空闲时控制器状态，不能视为通信恢复验证通过。需要现场核实型号、波特率、H/L 接线、终端电阻和收发器供电后再继续。

再次重新接线、USB 拔插和配置后，接口索引 7，初始 ERROR-ACTIVE、计数零。节点 1–4 只读查询仍无应答；追加 3 秒纯监听无接收帧，随后接口为 ERROR-PASSIVE，error-warning=3、error-passive=1、bus-off=0，TX/RX 各3帧24字节。未执行扩大扫描或运动。需提供实际型号、波特率、节点号并核实物理连接；不能以空闲时 ERROR-ACTIVE 登记通信通过。

## 电阻调整后恢复通信与实测完成

用户确认型号为 **DM-J10010L-2EC**，提供本地说明书V1.1（2026-03-30），并在怀疑120Ω电阻后调整接线/电阻配置，授权重新测试。随后在原1 Mbit/s速率下收到节点 **1**、Master ID **0**、模式 **MIT 1** 的寄存器应答。配置和型号说明书对照见[记录49](49_DM说明书核对与MIT适配.md)。调整后通信恢复与现场操作时间一致，但未测量调整前后电阻值，不能单独确定此前故障根因。

### 实际参数和额外修复

只读备份0–36及80、81共39个寄存器。`Gr=10`、`PMAX=12.5`、`VMAX=25`、`TMAX=200`、速度阻尼31=4、波特率代码35=4。**TIMEOUT寄存器9为0**，未修改；不能声称已具备经验证的电机自主失联停车。原后端固定45 rad/s、18 Nm不匹配本机，修复后按读回量程解码，不覆盖电机参数。

前两次ROS2初始化因100 ms模式应答期限失败，抓包有真实模式应答，没有使能。将配置寄存器期限改为有界500 ms后初始化通过。随后在使能前真实反馈检查失败，发现初始None intent不调度DM keepalive，而失能电机不会自行持续发状态。修复为模式确认后发送中性帧并设置Hold intent，取得失能态真实反馈，再允许进入运动。没有回退有效性检查。上述失败日志和CAN抓包全部保留。

最终使用 `/tmp/dm-fix-install` 产物、domain79、命名空间 `/dm_test`，仅注册can0节点1；50 Hz命令/控制循环、20 ms状态发布、direct超时0.2秒。调度器在Hold等状态按其原有50/100 ms节奏刷新；Run由实际控制命令触发反馈，不能把配置motor_query_hz直接等同于所有状态均50 Hz。速度与MIT配置依次启动，前一节点shutdown退出后才启动后一节点。
