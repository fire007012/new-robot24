# 系统概述与硬件拓扑

更新：2026-11-04。正式平台为 Ubuntu 22.04、ROS2 Humble、MoveIt 2 和 Gazebo Fortress。ROS1 源码在 `reference/ros1/`，只用于历史对照，不再提供 ROS1 回退链。

## 设备与所有权

整车使用 13 个物理关节，一个 `controller_manager` 和两个 `SystemInterface`，每个关节只有一个后端拥有。

| 后端 / 默认接口 | 设备 | 模式与用途 |
| --- | --- | --- |
| ros2_canopen / canable0 | 四摆臂，Node-ID 1、2、3、4 | 默认 CSV 9，可切换 CSP 8，切换需门控和实机验收 |
| ros2_canopen / canable0 | shoulder_yaw（6）、shoulder_pitch（5） | IP 7，组成机械臂前两轴 |
| can_driver / canable1 | elbow_pitch（0x13）、wrist_pitch（0x14）、wrist_yaw（0x15）、wrist_roll（0x16） | 私有 PP 协议、CSP，机械臂后四轴 |
| can_driver / canable1 | gripper（0x17） | 私有 PP 协议；米制位置接口，速度指令经受限积分转 CSP |
| can_driver / canable1 | 左右履带电机 | DM 速度控制，两轮成对管理 |

默认接口名和 1 Mbit/s 必须根据现场接线确认。CANopen 的 `DeviceContainer` 在 `RobotSystem` 内部，整车不再另外启动旧 CANopen 主站。六轴 JTC 同时使用两个后端的关节。

以上为当前配置的 13 个受控物理关节，不包含模型中的固定或从动关节。硬件所有权以 `robot_canopen_config/urdf/canopen.ros2_control.xacro`、`robot_hardware/urdf/private.ros2_control.xacro` 为准；CANopen Node-ID 来源为 `robot_canopen_config/config/legacy_joints.yaml`。

## 外围

- RealSense 驱动 4.58.1 配 librealsense 2.58.4；后置与夹爪相机用现场序列号绑定。
- Astra+ 使用 Orbbec SDK v1 的 ROS2 `main`，不能替换为不支持 Astra+ 的 SDK v2。
- `vision_pkg` 提供 RGB、深度投影、检测、全景及 H265；YOLO 权重须由部署现场提供。
- ArUco 与 easy_handeye2 负责检测及手眼标定。marker 字典、ID、尺寸和光学 frame 均须实测确认。
- `host_bridge` 提供 TCP/JSON 与视频控制；MediaMTX 和 RTSP 源按部署配置启用。
- CO₂、热成像通过各自外围包接入。

整车启动入口默认关闭上述外围，需按实际设备启用。`vision_pkg/cameras.launch.py` 独立入口默认后置 RealSense、关闭夹爪相机；整车入口启用夹爪相机时必须另外提供 `paw_serial`。USB 相机另由 `vision_pkg/usb_cameras.launch.py` 启动。手眼标定由 `eye_in_hand` 单独启动，自动走点使用项目 `ExecuteArmGoal`，不启用上游 `easy_handeye2` 的通用 MoveIt 运动辅助节点。

## 运行边界

软件测试已覆盖 mock、合成输入和 Fortress 物理仿真。真实硬件身份、方向、零点、软限位、IP/PDO、制动、载荷和相机外参尚待现场验收，不能用模拟值填入 commissioning 基线。
