# 电机实测后的 ROS2 完善建议

日期：2026-11-09。根据用户反馈，车上所有电机均已测试且能正常转动。本次结合记录 44–49 与当前工作树审阅代码，没有连接 CAN、使能电机或修改设备参数。逐轴现场结果仍以各自证据为准，用户的整体进展不自动替代整车控制和异常停止验收。

## 本轮软件完善（2026-11-09）

本轮已落实下述第 1 项 PP 参数一致性、第 2 项周期配置，以及第 3 项的只读内核统计采集。
第 1、2 项下文保留审阅时的缺口和设计依据；当前实现及验证结果见本节。
设备自主失联停止参数、装车方向/比例与现场 commissioned 登记仍需实机结果支持。

- PP：两入口使用 `PpDefaultVelocity.h` 共用换算、校验和后端设置；整车 joint 参数已接通。
- 周期：`ROBOT_CONTROL_PERIOD_MS=5/20` 联动全轴及六份单轴 bus、DCF 和插补配置；两种硬件 launch 自动推导 manager 频率并拒绝周期不一致。默认仍为 5 ms / 200 Hz。
- CAN：`tools/capture_can_health.py` 只读采集接口状态、队列设置和内核累计统计，计算相邻采样增量，接口重建或计数回退时拒绝比较。尚不测量目标帧排队和机械停止时间。

### 软件验证结果

- ROS2 Humble 下独立编译 11 个相关包成功，安装在 `/tmp/motor-improvements-install`；默认配置保持 200 Hz。
- 10 个受影响控制/通信/安全包的 **44 个 CTest 入口通过**。`colcon test-result` 汇总为 374 tests、0 errors、0 failures、4 skipped；跳过状态保留，不登记成全部底层用例均执行。
- PP 新增模拟发送帧检查，确认 ros2_control 的 joint 参数经初始化到达后端；1 rad/s 与 0.5 rad/s 分别编码为 10430 / 5215，方向不改变正速度幅值；非法参数在配置前拒绝，其他轴沿用默认值。
- 配置生成 6 个 Python 用例、周期一致性 2 个用例，以及 CAN 统计增量/接口重建/计数回退 2 个用例通过。其中前两组同时包含在上述 CTest 中。
- 200 Hz、50 Hz 两档分别完成 hybrid/single-axis 3 项和 group 1 项模拟测试。新增通过 ROS 参数服务读取 manager 实际 `update_rate` 的断言；最终启动日志也分别确认 200 / 50 Hz。
- 独立 50 Hz 配置安装在 `/tmp/motor-period20-install`；两档全轴及六单轴启动写入审计通过。同一配置构建目录完成 20→5→20 ms 切换，确认文件重新生成、七份配置一致。

中间验证发现 Humble 对节点专属 YAML 与追加通配参数的覆盖行为不符合原实现预期，曾出现“总线为 50 Hz、整车 manager 仍为 200 Hz”。现改为生成带明确 manager 频率的完整控制器参数文件，最终两档复测通过。中间分组测试另有一次夹爪单次命令观测超时，未定位该次根因；最终两档分组复跑通过，保留此前日志，不将复跑成功作为长期稳定性结论。首次沙箱内 UDP 测试因套接字权限失败，在允许本机通信的环境中复跑通过。

构建及 CTest 结果在 `/tmp/motor-improvements-build`、`/tmp/motor-improvements-log`；最终模拟日志为 `/tmp/motor-improvements-final-hybrid-{200,50}*.log` 和 `/tmp/motor-improvements-final-groups-{200,50}.log`。覆盖问题的中间日志为 `/tmp/motor-improvements-hybrid-50*.log` 和 `/tmp/motor-improvements-groups-50.log`。这些临时产物用于本轮复核，不是正式发布归档。

本轮未改设备参数、未连接真实 CAN 电机、未更新现场 commissioned，也未重跑整个工作区所有外围包。设备 watchdog、装车比例/方向、真实总线负载和停止时延仍需现场验证；F01–F13 状态保持原样。

- PH14：已增加限定身份和固件的零能力掩码兼容、非运行态模式切换、停止态兼容及反馈时间戳竞态修复。
- PH17：修正逐点下发定时后，线性运动反馈速度标准差从约 0.208/0.244 降至约 0.0063/0.0062 rad/s；随后新增 standalone 驱动内完整位置计划入口。

这些能力已存在，不建议再重复实现。特别是整车已有 JTC 插补及控制器超时机制，应复测和补缺口。

## 优先完善项目

### 1. 补齐 PP 两个入口的配置一致性

**已确认的代码缺口。** `can_driver/src/can_driver_node.cpp` 读取 `pp_position_default_velocity` / `pp_csp_default_velocity`，并在初始化时调用 PP 后端的每轴默认速度设置；`can_driver/src/can_driver_system.cpp` 的 `on_init()` 和 `initDevices()` 尚未处理这两项。

建议在 ros2_control 入口增加同名 joint 参数、相同的有限值/正数/原始单位分辨率/溢出校验，并在模式初始化前传给后端。两入口最好共用换算与校验，避免继续分叉。省略参数应保持现有默认行为；整车 xacro 的实际数值需结合机构确认。

验证：配置解析与模拟传输检查合法值正确传递、非法值拒绝、未配置行为保持；再单轴检查整车插件路径实际发送的速度字段。夹爪使用线性单位，不能照搬裸 PP 的 1 rad/s。后端默认速度设置也不能替代上层轨迹限速。

### 2. 将控制周期作为整套配置共同约束

**已确认的实测覆盖差异。** PH14/PH17 成功测试使用 50 Hz；`robot_hardware/config/controllers.yaml` 的 manager 为 200 Hz，`robot_canopen_config/scripts/generate_bus.py` 固定驱动周期 5 ms、SYNC 5000 μs、插补周期对象 5 ms。当前生成器也将历史 200 Hz 作为校验条件。

建议增加明确的调试周期配置，统一生成 manager、驱动、SYNC 和插补周期，并审计四者匹配。保留当前 200 Hz 基线，另提供可复现的 50 Hz 调试配置；不能只改 Python 发点周期或单独调低 manager。逐步测量单轴、同总线多轴、双后端六轴的周期分布、反馈期限和总线负载，再确定实际运行频率。

整车继续由现有 `RetainedJointTrajectoryController` 负责插补，不叠加 standalone 完整计划执行器。轨迹需要平滑端点时，上层应提供合适的速度/加速度边界并验证实际插补结果。

### 3. 完善 CAN 运行诊断与积压观测

**已有基础，建议扩展。** `SocketCanController` 已区分 ENOBUFS 等发送回压与链路不可用；`bringup_canable0.sh` / `bringup_canable1.sh` 已设置 txqueuelen，默认 10000，而单轴成功记录使用 1000。

建议统一导出接口状态、发送失败、回压、收发错误、bus-off 和计数增量，并与控制周期、反馈年龄放到同一采集结果。长时间运行应比较测试前后增量，不把历史累计数直接归因于本轮。

队列大小应结合发送延迟测量选择：增大队列可能减轻丢帧，也可能使旧目标等待更久。需测量 halt 后最后一个旧运动帧及实际停止时间，不能仅用“没有 ENOBUFS”判断改善。总线异常后的运行许可恢复仍沿用显式恢复流程。

### 4. 区分上层超时停止与设备自主失联停止

**现场待验证项。** DM 记录中 TIMEOUT 寄存器 9 为 0；已实现的 direct 超时依赖驱动继续运行。整车履带、摆臂 CSV、Servo 和夹爪控制器也已有各自命令超时。有限位置计划则允许提交客户端退出后继续执行已接收计划，不能统一改成停发即停。

建议分别验证命令源停止、控制器退出、驱动进程退出、CAN 断开四类情况，记录许可撤销和真实机械停止时间。核对设备 watchdog/心跳消费者的能力、单位和停止动作后，再决定部署参数。修改电机超时应单独备份和读回，不根据本次审阅直接写入设备。

### 5. 把裸电机结果落实为装车逐轴基线

**已确认的配置待登记。** `robot_hardware/config/commissioning.yaml` 仍为未登记模板；这是现场身份和方向未完成核验时的合理状态。整车 DM 配置仍为节点 7/5、Master ID 8/6，实测裸 DM 为节点 1、Master ID 0，两者不能直接互换。

建议通过已有 snapshot/commission 工具逐轴记录物理位置、节点与反馈 ID、身份/固件、方向、输出端比例、零点、限位和实际模式。装车核验后再登记 commissioned。PP 夹爪按米制、摆臂按实际外部传动、履带按输出端角速度标定；编码器到达不能替代外部角度或距离测量。

DM 的 Kp=200/Kd=4 是一次裸电机 MIT 测试结果，不应迁入整车履带速度模式，也不应当作带载机构的通用增益。

## 建议实施顺序与验证范围

先补 PP 参数一致性和周期配置，再增加统一诊断采集，随后依次完成装车单轴、同组多轴、跨后端轨迹与异常停止复测。新增配置和驱动变更完成专项回归后，重新运行整车离线回归，锁定主仓库及两个有修改子模块的匹配版本。

最初审阅只完成静态核对；后续本轮实现与验证以本文“本轮软件完善”节为准，没有将已有实测结论扩展到新范围。具体证据和未完成项见 [PP 44](44_PP单电机实机验证记录.md)、[PH14 45](45_PH14单电机实机验证记录.md)、[PH17 46](46_PH17单电机实机验证记录.md)、[CSP 47](47_CSP位置抖动根因与轨迹执行修复.md)、[DM 48](48_DM单电机实机验证记录.md) 及 [清单 36](36_ROS2迁移剩余事项清单.md)。
