# 三组预设与上位机对接提示词

日期：2026-11-12。机器人端实现位于 `host_bridge/motion_presets.py`、`control_v2.py` 和 `output_adapters.py`。本页后面的提示词可直接交给上位机开发助手。

## 机器人端约定

| 预设 ID | 显示名称 | 底层运行组 |
| --- | --- | --- |
| `flippers` | 摆臂 | `flippers` |
| `base` | 底盘 | `base` |
| `arm` | 机械臂（含夹爪） | `arm`、`gripper` |

三组支持任意非空组合，共七种；全车就是三个 ID 全选，不使用额外的 `all` ID。夹爪不作为独立选项。底层四组隔离和关联策略保持有效。

预设控制运动组的初始化、使能、运行和停止，共用唯一 controller_manager 和总线主站。`robot_manager` 的 `hardware/mock` 仍选择实机/模拟软件栈；管理 API 的 `start` 只启动软件，不代表电机已使能。MoveIt 等软件节点可以共存，未选择的运动组不因软件启动而初始化或运行。

新能力是控制协议 v2 的可选扩展 `motion_presets_v1`。未协商该扩展的旧 v2 客户端保留全车许可、全车生命周期服务语义；不能使用 `presets` 参数。新客户端应明确发送所选预设，省略时默认全选。

## 可直接复制的上位机开发提示词

请修改当前上位机项目，对接机器人端已经实现的“三组运动预设”。先阅读项目自身开发约束和现有 TCP、管理 API、控制会话代码，然后直接完成实现与测试，不只给出方案。以以下约定为本次对接依据，不要沿用旧文档中“所有四组必须 Running 才允许运动”的客户端判断。

### 1. 页面和模型

提供三个可多选的预设：摆臂 `flippers`、底盘 `base`、机械臂（含夹爪）`arm`。机械臂映射到两个底层组 `arm/gripper`，统一选择和操作。支持单组、任意双组、全车三组。运行请求的选择不能为空；全不选的界面状态可保留，但禁用启动/授权，停止全部使用明确的停止操作。

区分“本地待提交选择”“机器人确认的 selected_presets”“实际运行状态”。勾选不触发使能或运动。全车按钮相当于选择三个预设。实机/Mock、视频选择与运动预设分开建模。

每个预设展示选择状态、每个底层组状态、运行许可及阻断诊断。机械臂必须 `arm` 和 `gripper` 都满足目标状态，才能显示该预设成功；一个成功一个失败时展示部分失败和两者详情。组合操作可能部分成功，不承诺原子事务或自动回滚，不能把总响应失败理解为所有组均已停止。

### 2. 能力发现与握手

TCP 使用现有每行一个 JSON 的帧格式。连接后的 `capabilities` 增加：

```json
{
  "control_protocol_version": 2,
  "control_capabilities": ["session_v2", "freshness_v2", "explicit_authorization", "bounded_operations", "isolated_output", "runtime_permission", "motion_presets_v1"],
  "motion_presets": {
    "flippers": {"label": "摆臂", "groups": ["flippers"]},
    "base": {"label": "底盘", "groups": ["base"]},
    "arm": {"label": "机械臂（含夹爪）", "groups": ["arm", "gripper"]}
  }
}
```

以上是相关字段摘录，其他已有字段仍保留。只有服务端声明 `motion_presets_v1` 才开放分组界面；旧服务端不能默默降级为全车启动。

在连接后三秒内发送握手，例如选摆臂和机械臂：

```json
{
  "type": "control_hello",
  "protocol_version": 2,
  "robot_id": "robot24",
  "role": "control",
  "capabilities": ["session_v2", "freshness_v2", "explicit_authorization", "bounded_operations", "isolated_output", "runtime_permission", "motion_presets_v1"],
  "presets": ["flippers", "arm"]
}
```

`robot_id` 使用实际部署值。保存响应 `result` 中的 `session_id/epoch/freshness_token` 和服务端确认的 `selected_presets/selected_groups`。监控端使用 `role: monitor`，只能查询，不取得控制权。`control_status` 展示当前控制所有者的预设选择，监控者的握手不更改该选择。

### 3. 操作报文与启动流程

继续使用已有控制 v2 会话、新鲜度、递增 seq、300 ms 以内 TTL 和显式授权。不要用普通 heartbeat 替代 `freshness_request`，不要重放旧操作输入。

以下是报文模板，尖括号字段必须替换为当前会话值：

```json
{
  "type": "system_command",
  "protocol_version": 2,
  "session_id": "<session_id>",
  "epoch": "<epoch>",
  "freshness_token": "<freshness_token>",
  "seq": 12,
  "ttl_ms": 300,
  "request_id": "<全局唯一操作ID>",
  "command": "init",
  "params": {"presets": ["flippers", "arm"]}
}
```

`params.presets` 可省略，表示当前会话所选全部预设；如提供，只能是所选预设的非空子集。未知 ID、重复 ID、未选中预设和原始 `groups/resource` 参数都会被拒绝。新的预设客户端生命周期请求只允许 `params.presets`，不能借此调用任意服务。

`command` 支持 `init/enable/resume/halt/recover/shutdown`；兼容命令 `disable` 在预设模式中映射为组 `halt`，界面请使用“停止”并发送 `halt`，不要称为设备断电。

启动按钮实现以下状态机：

1. 通过已有管理 API 启动所需的软件栈，确认软件 ready；不要为每个运动预设分别启动一套软件或总线主站。
2. 建立控制会话，确认机器人端选择；发送中立 `operator_input`，再发 `authorize_operations`。
3. 对目标预设发送 `init`，轮询 `operation_query` 至终态，同时读取运行状态。
4. 使用当前 epoch、新 token、中立输入和操作授权发送 `enable`；到 Armed 后才允许继续。
5. 用相同方式显式发送 `resume`，确认目标底层组全部 Running。
6. 操作完成、状态新鲜且无阻断后，再发送新中立输入、`authorize`，启用连续键盘/手柄控制。

已有组处于其他状态时，按实际状态选择步骤，不能对 Running 的组重复 `init/enable`。故障恢复使用显式 `recover`，它只恢复到 Armed，之后仍需显式 `resume` 和新授权。

每个生命周期/模式操作执行前会暂停遥控输入；操作中 `authorize` 返回 `OPERATIONS_BUSY`。运行组或输入代数变化可能更新全局 epoch、清除 token 和操作授权，正在执行的操作也可能返回 `invalidated: true`。每一步之后都通过 `control_status` 读取最新 epoch，再请求新 token、发送中立输入、重新取得需要的授权；不要提前批量排队三步，也不要把 invalidated 当成底层没有执行。

### 4. 查询结果和状态

`control_status` 请求包含 `type/protocol_version/session_id`，无需新鲜度 token，也允许使用旧 epoch 找到最新 epoch；其他已有查询约定不变。其 `result` 新增：

- `selected_presets`、`selected_groups`：机器人端确认的选择。
- `runtime_fresh`：运行反馈是否在一秒期限内。
- `operations_authorized`：当前是否获得操作授权。
- `presets.<id>.label/groups/selected`：定义和选择状态。
- `presets.<id>.states`：按底层组给出的实际状态，缺失为 `Unknown`。
- `presets.<id>.diagnostics`：底层组诊断，包括 ready、blockers 和底层许可状态。
- `presets.<id>.motion_permitted`：该预设实际运行许可，不代表已选择或已获得遥控授权。
- 顶层 `motion_permitted`：当前所选组合是否全部允许运动；仍需 `authorized` 才能遥控。

反馈过期时，旧 states 可以继续用于追溯，但必须显示为过期并禁用运动，不能用缓存 Running 冒充当前状态。未选择组的 Fault 不直接代替所选组许可判断；底层关联条件、全局禁止和所有者心跳仍有权阻断所选组。

操作受理返回 `operation_id`，不是完成。用 `operation_query` 查询终态 `succeeded/failed/result_unknown`，不要把 accepted/running 显示为启动成功。记录增加 `presets/groups/preset_aware`。预设生命周期的 `result` 是数组，其中条目含：

```json
{
  "success": false,
  "operation_id": "<底层runtime操作ID>",
  "message": "<底层JSON文本，含reason/groups/operations>",
  "presets": ["arm"],
  "requested_groups": ["arm", "gripper"]
}
```

外层控制操作 ID 和这里的底层 runtime 操作 ID 是两个不同字段作用域，不要混用。`message` 可尝试解析 JSON，失败时保留原文。将其中组状态与 `control_status` 的新鲜状态共同展示。超时标为结果未知，禁止自动重发 enable/resume；先查询状态并由操作员确认。相同 request_id、相同请求用于查询式重试，会返回原操作；不同语义必须生成新 request_id。尤其改变预设后，即使 command 相同，也必须使用新 ID。

### 5. 增加、取消或切换预设

使用 `type: select_presets`，带正常的会话、新鲜度、seq、TTL 字段，以及顶层 `presets` 数组。先发送新中立输入；没有 accepted/running 操作时才允许变更。它是即时会话选择，不是后台 operation，也不初始化或启动电机。

增加示例：从底盘扩大为底盘+机械臂，提交 `presets: ["base","arm"]`。成功后旧输入和两种授权都被清除，epoch 更新；底盘不会因此重建或重启。刷新会话后，仅对新增 `arm` 预设执行所需 init/enable/resume，不要对已有 Running 的底盘再次 init。全部所选组满足条件后重新授权遥控。此期间健康组可以保持 Running，但连续遥控输入会暂停并发零值。

取消示例：底盘+摆臂改为仅底盘，先对 `params.presets: ["flippers"]` 发 halt，等待摆臂停止并取得新鲜反馈，再提交 `select_presets`。移除组要求软件状态为 Stopped/Halted、底层诊断可读且许可状态为停止或 Fault；不能只根据按钮勾选或 RPC 已受理判断。机械臂取消需同时满足 arm 和 gripper。最后刷新 token 和授权。

选择成功响应直接返回新 epoch、selected_presets、selected_groups 和授权 false，不返回新 token；随后使用新 epoch 发 `freshness_request`。状态变化也可能再次更新 epoch，因此统一通过状态同步处理。

### 6. 输入、模式与急停

沿用现有 vehicle/arm 操作模式和键盘/手柄映射。预设决定哪些组允许运行，操作模式决定输入映射，两者不要混用。vehicle 模式可操作已选中的底盘和摆臂，arm 模式可操作已选中的机械臂和夹爪；同时启用三组不等于同一手柄轴同时驱动所有组。

机器人端过滤未选中组的连续运动输出；上位机也应禁用相应控件。未选 arm 时，机械臂命名目标及 arm 模式请求返回 `PRESET_NOT_SELECTED`。选择 vehicle 模式且未选 arm 时，不调用机械臂模式服务。

机械臂遥控依赖 Servo 部署：软件启动时需要 `enable_servo:=true`，并显式成功切换 `set_control_mode` 的 `params.mode: arm`。robot_manager 已支持部署档案布尔字段 `enable_servo`，hardware/mock 示例均为 true；已有部署省略字段时仍为 false，部署管理员需离线修改档案并受控重启软件，该字段不能通过在线配置事务修改。默认 trajectory 路径可用命名目标；缺少 Servo 时显示明确原因，不能把切换失败当成功。切换回 vehicle 会恢复机械臂 trajectory 模式（若选中了 arm）。

全局急停、失联、看门狗和全局禁止继续保留。`emergency_stop` 始终作用全车，不随预设缩小；普通组停止使用前述 halt 子集操作。清除急停不自动恢复 Running 或遥控授权。底盘需要的机械臂安全姿态、摆臂支撑及机械臂需要的夹爪载荷条件仍须真实可信证据，不能通过客户端把 unknown 改成 true。

### 7. 错误与验收

新增错误至少处理：`PRESETS`（空、未知、重复或非法类型）、`PRESET_NOT_SELECTED`、`HALT_REMOVED_PRESETS`、`OPERATIONS_BUSY`。沿用 `CAPABILITIES/NEUTRAL_REQUIRED/EPOCH/STALE_TOKEN/NOT_AUTHORIZED/RUNTIME_PERMISSION` 等现有错误，展示可操作原因，禁止静默全车回退。

至少覆盖七种组合；arm 与 gripper 部分失败；未选组不能输出运动；已选组反馈过期或失去许可；增加预设仅初始化新增组；取消前必须停组；选择变化后旧输入/旧 token/旧 epoch 无效；请求幂等与结果未知；旧服务端能力不足；监控连接不改变选择；急停始终覆盖全车。用协议模拟测试完成离线验收，并将真实上位机与机器人联调单独记录。

```bash

python3 -m unittest discover -s robot_manager/tests -v
PYTHONPATH=robot_hardware python3 -m unittest discover -s robot_hardware/test -p test_groups.py -v
```
