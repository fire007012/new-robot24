# 分组隔离与局部恢复实施验收

日期：2026-10-25；最终离线验收：2026-10-26。对应 [计划 29](29_分组故障隔离与局部恢复执行计划.md)。本文记录分组运行实现、离线验证和现场操作增量；[记录 30](30_分组事件合同与第一阶段实施记录.md) 保留为第一阶段历史记录；已完成批次的原始证据已清理。

整车 `robot_bringup/full_system.launch.py` 默认传入分组 `group_policy`；直接启动底层 `robot_hardware/hardware.launch.py` 且策略为空时才使用全局联锁。`activation: staged` 表示尚未通过现场发布验收，并非禁止离线模拟验证。现场物理条件没有可信输入时始终为 unknown，不能用修改 YAML 初值或调用模拟服务代替现场证据。未连接真实电机，P6 的物理停止、承载、制动和匹配提交发布仍待现场执行。

## 1. 实现与边界

| 层 | 实现及停止范围 |
| --- | --- |
| `robot_safety` | 四组独立 ready、状态和 epoch；结构化事件、告警计数、传递关联、有效期证据、显式确认和全局禁止；拒绝同一 domain 混用新旧写入者或不同策略 |
| CANopen | 唯一 DeviceContainer/主站；先创建驱动元数据，仅初始化选中组通信；隔离已清理的单节点 boot 失败，共享配置错误仍拒绝配置；读写局部关闭许可，轴不可读返回 NaN；停止资源可以在设备失联时释放 |
| 私有 CAN | 仅准备选中组；首次使能前安全预置并确认真实反馈；按字段记录反馈时间，其他应答不能刷新位置期限；单轴故障停所属组，共享通道失败覆盖其全部轴 |
| 协调层 | `init/enable/resume/halt/recover/shutdown` 显式选组，资源恢复单独选择后端；每组互斥、共享资源锁、操作 ID、超时后等待远端实际结束；局部恢复只到 Armed |
| 调用层 | 按请求组检查活动控制器和实际占用接口；摆臂会话单独切换；维护 journal 按目标轴阻断；状态广播器在新增反馈接口后更新，运动控制器不因这一更新重启 |
| 输入会话 | 履带控制器保留标准差速接口、里程计和限幅，激活时清除缓存 Twist 与限速历史，并隔离旧回调；摆臂参考按组会话代数清除；恢复需显式启动和新目标 |
| 所有者失联 | C++ 写入许可要求协调器每 100 ms 更新的单调时钟心跳，1 s 期限；到期全局锁存停止。迟到心跳不能延长已经失效的旧租约，恢复心跳不自动清除禁止；新协调器接管旧 Armed/Running 会话先全局停止并释放旧控制器 |

机械臂的两肩与肘腕四轴在同一共享 Domain 上检查 `arm` 许可，故障传播发生在硬件周期内。Python 负责随后停止控制器和取消轨迹，不承担首次关闭两个后端写入的职责。完整组件生命周期仅用于确需重建共享资源的操作，普通组 recover 不重建总线。

CANopen 分别跟踪状态字、模式、位置、速度 PDO 的时间；私有 CAN 分别跟踪位置、速度、模式、使能和故障字段。支持后端、轴和字段的告警/停止/稳定时间覆盖：CANopen 默认 50/100/100 ms，私有 CAN 默认 250/500/100 ms。到达硬上限、硬故障、心跳或 NMT 失效立即撤销许可；Warn 不能超越停止上限。当前实际私有轴使用 PP/DM；不能提供模式/使能可信回读的其他协议保持不可准备，不用本地命令冒充设备确认。

停止动作发起失败会记录，软件仍关闭许可并释放本地占用。私有发送队列和内核/设备可能存在已发送或排队的帧；离线测试不证明物理停机时延。CANopen `halt_motor` 的本地命令撤销不等待失联驱动答复，后续制动效果须实测。

三个关联条件为 `arm_secured`、`support_trusted`、`payload_retained`，对应策略指定的来源；缺失、来源不符、过期或 unknown 均阻断依赖组。真实硬件没有提供“强制条件为 true”的 ROS 服务。现场需落实可信采集并通过有期限的 Domain 证据入口接入。未分类 EMCY 保留原码并组停止；当前没有有依据的厂商错误码降级白名单。

## 2. 分组运行入口

离线模拟示例：

```bash
source /tmp/group-verified-install/setup.bash
ros2 launch robot_hardware hardware.launch.py mock:=true \
  group_policy:="$(ros2 pkg prefix robot_safety)/share/robot_safety/config/group_policy_v1.yaml" \
  journal:=/tmp/group-demo-maintenance.json
ros2 run robot_hardware robot_group init base
ros2 run robot_hardware robot_group enable base
```

此时未准备的机械臂/摆臂没有可信姿态和支撑证据，底盘使能应被拒绝。**仅模拟插件**提供 `/mock/conditions/arm_secured`、`support_trusted`、`payload_retained` 的 SetBool 注入，用于验证关联规则；不用于实际运行。条件满足后对故障组执行 recover，再显式 resume：

```bash
ros2 run robot_hardware robot_group recover base
ros2 run robot_hardware robot_group resume base
ros2 run robot_hardware robot_group halt arm
ros2 run robot_hardware robot_group recover arm
# arm 只到 Armed；新 resume 后再发送新六轴目标。
ros2 run robot_hardware robot_group resume arm
ros2 run robot_hardware robot_group recover_resource --resource RobotCanopenSystem
```

资源恢复停止使用该组件的全部组：重建 CANopen 涉及 arm/flippers；重建私有 CAN 涉及 arm/base/gripper。另一个健康后端不重建，跨后端 arm 仍要重新准备。全组选取使用 `--all`。原 Trigger 全车入口保留，其语义为显式全选四组。

ROS 服务 `/robot_runtime/group_operation` 类型为 `robot_hardware/srv/GroupOperation`，请求包含 `groups/operation/resource`，响应包含 `success/operation_id/message`。拒绝未知组、重复组、非法状态和资源选择；响应超时不能据此判定远端取消。`/robot_runtime/state` 展示组状态、操作进度、dirty 轴和诊断；C++ `/robot_runtime/status` 在协调器失效时仍可读，含实际许可、epoch、事件、关联阻断及所有者心跳状态。Python 监控对旧会话快照不执行新会话停机，积压监控回调不挤占全部 RPC 完成线程。

```bash
ros2 service call /robot_runtime/status std_srvs/srv/Trigger '{}'
ros2 run robot_hardware robot_group global_stop
ros2 run robot_hardware robot_group reset_global_stop
ros2 run robot_hardware robot_group recover base
```

心跳失联或显式全局停止后，先处理原因、恢复协调器，再显式 reset；reset 本身不恢复 Running，仍需 recover/resume 和新命令。组操作不能绕过全局禁止。

## 3. 维护与故障处理

分组模式的 `/robot_runtime/maintain` 先关闭目标所属组许可、停止其控制器并 disable 目标轴，验证目标身份/PDO 后在唯一主站上维护。其他组能否继续由关联矩阵决定；不执行全组件停用。参数错误在停机前拒绝。`set_offset/limits/...` 和单位沿用 [验收单 28](28_CANopen软件交付与实机验收.md)。

保存/回滚不确定会留下 journal，并建立 `maintenance_uncertain` 锁。restore 要匹配 journal 的目标轴，先验证身份，再恢复/保存/读回；journal 清理后还须 fresh prepare、显式清锁和 arm。其他轴的干净组可按关联条件运行，未定目标的旧 journal 则保守限制全部轴。持久化是否成功仍须现场重启读回。

完整管理器运行时，`axis_commission` 只读检查不再停用完整硬件；维护委托运行协调器，禁止以该工具直接激活整车组件。单轴独立管理器仍支持原调试流程。离线设备读请求返回失败，采集工具把无效反馈写为 JSON null 并附有效标志。

## 4. 离线验证与证据

统一入口为 `robot_hardware/scripts/validate_offline.sh /tmp/group-verified`。包含空前缀构建、生成配置审计、十个包的 CTest、原全局联锁整链与真实未配置单轴插件、分组整链故障注入。搬迁检查复制安装目录并暂时移走原目录，在清理旧环境路径的新 shell 中核验配置、加载真实未配置插件并执行分组整链，结束后恢复原目录。

| 验收目标 | 覆盖入口 |
| --- | --- |
| 关联 unknown、过期、来源不符及传递传播；硬上限与稳定窗口 | `test_group_domain`、`test_freshness`、`test_motion_health` |
| 配置所有权/控制器冲突、非法阈值、混用新旧写入者 | `test_policy`、`test_group_contract`、拓扑检查 |
| CANopen 节点 boot 隔离、部分失败重试、配置错误不降级 | `test_node_isolation` |
| 真实 SystemInterface 的逐轴 NaN、整组输出预检、跨后端组关闭、共享通道失败、原始 EMCY、停止资源释放 | `test_grouped_system`、`test_grouped_robot_system`、`test_cia402_data` |
| 长准备不阻塞无关停止、部分成功、操作追踪、维护参数拒绝、旧监控快照、新所有者接管 | `test_groups.py` |
| 单独底盘、轨迹取消/健康轨迹完成、履带成对停止、接口仍可用、延迟准备围栏、摆臂切换及旧输入隔离、维护失败与恢复 | Humble `group_smoke.py`，两个模拟硬件、真实控制管理器和运动控制器 |
| 进程 SIGSTOP 心跳失效、恢复后锁存、显式全局停止和局部恢复不能绕过 | 同一分组整链，C++ guard 与 Python 协调器为独立进程 |
| 原单位/范围/IP 镜像/SDO/身份/PDO、首次使能和旧全局行为 | 原上游/项目 CTest、`audit_config.py`、`hybrid_smoke.py` |

最终离线验证已通过：40 个 CTest 入口、321 个 GTest 用例（另有 4 个原有禁用用例未执行）、40 个 Python 单测，以及原前缀/搬迁前缀合计 7 个进程级测试；这些计数按层分别统计，不能与 CTest 入口数相加作为唯一用例总数。本页保留当时计数，原始日志和校验值文件已清理，可按统一入口重新生成。工作树仍包含两个子模块的未提交补丁，不能只用旧 gitlink 交付。正式匹配提交和发布标签在 P6 实机通过后生成。

## 5. 现场未完成项

现场使用 [现场验收记录模板 32](32_分组隔离现场验收记录模板.md) 逐项填写计划 29 的 P6，至少记录：三类关联条件的传感器/制动/姿态/载荷依据及有效期限；轴/通道断线、EMCY、协调器失效、全局急停的真实停止时延；失联驱动独立停止/制动行为；恢复无跳变、无旧目标重放；健康组是否物理连续运行；真实保存、掉电与恢复读回。当前软件阈值是待现场核验的默认值，不构成实时性或制动性能承诺。

底层空 group_policy 的全局模式仅保留为 ROS2 诊断入口；整车默认分组模式。回退前停止组、关闭组件并确认主站退出；涉及设备参数时另按维护基线恢复，不能仅靠替换提交恢复设备参数。
