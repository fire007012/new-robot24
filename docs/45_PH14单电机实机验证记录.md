# PH14 单电机实机验证记录

日期：2026-11-08。用户接入并确认 PH14 为裸电机。首轮完成通信和参数备份，但模式请求被拒绝，未转动；随后参考 ROS1 控制流程完成兼容修复，**CSV 正反向低速实测通过**：反馈位移约 +2.197° / −2.317°，结束后停止失能。修复与复测见本文末节；50 Hz 单轴结果不代替整车或 200 Hz 验收。

## 设备与软件

- USB CAN：`1d50:606f`，`gs_usb`，`can0`，1 Mbit/s。用户将发送队列从 10 扩大至 1000。
- 实测协议为 CANopen，Node-ID **2**，与记录 44 的 PP 私有协议电机不同。
- 固件：`V133-0262`；`1000:00=0x00220811`；厂商 `1640`、产品 `0x00221401`、修订 `16`、序列号 `0x002C0025`。
- 初始位置 **1213 count**、速度 **0**、状态字 **0x0250**（未使能）、故障码 **0**；初始模式 **1**。
- 主仓库 `92608d3879b42e96ff3d7f1ee2a13347d1730d0f`；`ros2_canopen` 为 `90e7ce79f8920edbf429552c09b71026774f1411`，本次没有修改其源码。

编译得到 6 个 CANopen 主站/通信/CiA402 包。初次构建额外选中的 `canopen_ros2_control` 因未 source `robot_safety` 产物失败；加载此前已构建的 `/tmp/pp-motor-check-install` 后，补建 `canopen_ros2_control` 和 `robot_canopen_config` 成功。没有执行完整软件回归。

运行的是独立 `Cia402Driver` 服务入口，`managed_by_ros2_control: false`，保留 `motion_safety: true`、100 ms 反馈期限，关闭启动 Homing。没有将未登记现场基线改成 commissioned，也没有宣称整车 ros2_control 或分组运行通过。

## 启动与模式请求

1. 只读扫描发现 `0x582` SDO 应答，备份身份、固件、状态、原 PDO、心跳、模式、零偏和限位。原零偏为 0，软限位上下界为 int32 极值，厂商限位使能对象 `0x2003=0`。
2. 运行时配置由仓库 Node-ID 2 单轴配置派生，按裸电机 `6091:01/02=6619136` 和历史换算依据使用 6619136 count/圈，未套用摆臂三倍外部传动比例。该换算未进行外部角度校准，实际也没有发送运动目标。
3. 首次直接从源码目录启动，DCF 引用 `./ph14_motor.bin` 不能按预期加载，配置下载失败。改为从配置目录启动，开始正常配置下载。该现象属于 standalone 入口，不能据此推断整车插件的路径处理也失败。
4. 200 Hz 配置下，设备 SDO 应答及时，但主站后续 SDO 请求间隔逐渐扩大，超过 5 秒启动期限。尚未确定根因；不能仅凭这一结果认定 CAN 卡吞吐上限。
5. 临时将单轴 SYNC 和驱动周期改为 **20 ms / 50 Hz**，启动期限设为 15 秒，易失插补周期设为 20 ms，主站约 **0.49 秒** 完成 boot，并收到 NMT START。200 Hz 未通过。
6. 通过 ROS2 `/ph14_motor/sdo_read` 再次读取 **`0x6502:00=0`**。请求 `/ph14_motor/cyclic_velocity_mode` 和 `/ph14_motor/position_mode` 均返回 **false**，日志显示 `Mode is not supported.`。

当前驱动以真实 `0x6502` 位掩码判断模式支持；该固件返回 0 导致模式分配被拒绝。这个结果说明现有驱动与该固件的能力上报存在兼容性缺口，**不能直接推断电机本身不具备任何运动模式**。没有使用 EDS 中 `0x03CD` 默认值覆盖实测，也没有通过手写控制字或伪造能力字段来绕过拒绝。

本次没有调用 init/enable，也没有发送非零运动目标。原计划的 0.02 rad/s、2 秒小幅测试没有执行，位置一直保持 **1213 count**。

## 结束与恢复

主站退出后，将原心跳、插补周期和模式逐项恢复。通信复位未恢复原 PDO 映射，随后按原始备份逐项恢复 PDO 通信和映射对象，120 次写入均有成功应答。最终重新读取完整备份集合，与测试前比较 **无差异**，见 `restore-comparison-final.json`。

最终状态：位置 **1213 count**、速度 **0**、状态字 **0x0250**、故障码 **0**、模式 **1**。零偏、限位、PDO、心跳和插补周期均读回一致，没有写保存或恢复出厂对象。CAN 最后统计 error-warning、error-passive、bus-off 均为 **0**；队列保持用户设定的 1000。ROS2 主站和采集进程已退出。

首轮结论为模式能力上报与现有驱动不兼容，不能登记为成功转动。后续修复与复测如下，原失败证据继续保留。

原始读回、配置、三次启动日志/抓包、模式请求结果、恢复脚本和读回比较位于 [证据目录](evidence/20261108-ph14-single-axis/)。临时构建产物位于 `/tmp/ph14-motor-check-install`。

## 同日兼容修复与正反向复测

### ROS1 参考依据

- [Eyou_Canopen_Master 的模式服务](../reference/ros1/Eyou_Canopen_Master/src/canopen_aux_services.cpp)：明确允许项目使用的 IP/CSP/CSV 等模式，在 Standby 修改模式，没有依赖 `6502` 位掩码。
- [AxisDriver](../reference/ros1/Eyou_Canopen_Master/src/axis_driver.cpp)：写入 `6060`，读取真实 `6061` 和状态字；OnBoot 预置模式与 Shutdown 控制字，防止初始 PDO 的零值覆盖模式。
- [CiA402 状态机](../reference/ros1/Eyou_Canopen_Master/src/cia402_state_machine.cpp)与 [AxisLogic](../reference/ros1/Eyou_Canopen_Master/src/axis_logic.cpp)：停止时收回命令，使用当前位置/零速安全目标，新使能和恢复使用新的命令代次。
- [Eyou_ROS1_Master 混合启动](../reference/ros1/Eyou_ROS1_Master/src/hybrid_auto_startup.cpp)：区分 init、Armed 和显式 release，不将恢复等同于自动运行。

### 修改内容

1. **限定设备的零能力掩码兼容**：通用驱动新增 `enable_eyou_zero_mode_support_fallback`，默认关闭；项目生成配置显式启用。只有真实 `1000=0x00220811`、厂商 `0x668`、产品 `0x00221401`、修订 `16`、固件 `V133-0262` 且 `6502=0` 时，允许尝试模式 7/8/9。SDO 失败拒绝激活，身份不符仍拒绝模式；设备上报非零掩码时完全以该掩码为准。没有写入 `6502` 或使用 EDS 的能力默认值替代读回。
2. **在非运行态切换模式**：项目生成 `switching_state: 4`，先退出 Operation Enable 到 Switched On，再写模式并等待真实 `6061`。实机证明原先在 Operation Enable 下切换 CSV 超时，改为上述流程后成功。模式确认、状态和健康条件全部满足后才打开新命令会话。
3. **兼容 Quick Stop 最终失能态**：认可真实 Quick Stop Active 和 Switch On Disabled 两种停止确认。disable 请求 Switch On Disabled，避免固件在停止过程中自动失能时，仍请求切换到 Switched On 而失败；不会在 disable/shutdown 中自动复位并发故障。重新开始仍需显式 init/模式确认和新目标。
4. **修复反馈健康检查的并发时间戳竞态**：原实现通过默认参数在加锁前取时，可能把另一线程更新的反馈误判为时间倒退，从而误撤销会话。压力测试的 10 万次查询在修复前使 epoch 从 0 误增至 4992；改为加锁后取实时钟后为 0。显式时间参数仍可用于真实过期/时间回退回归，100 ms 反馈期限未放宽。
5. 缺少 driver 时不再使用原先测试用的“健康”默认值，避免空驱动被当作可尝试建立会话。

### 最终实机结果

本轮仍为单节点 standalone，SYNC/轮询 **50 Hz**、反馈停止期限 **100 ms**，每次运行约 2 秒，速度命令 ±0.02 rad/s。

| 项目 | 最终结果 |
| --- | --- |
| 正向 CSV | 反馈位移 **+2.197156849°**；42 次服务请求全部成功 |
| 停止后重新建立会话、反向 CSV | 反馈位移 **−2.316701153°**；42 次服务请求全部成功 |
| 两次停止结果 | 主动零速、halt、disable 均成功；最终状态字 **0x0250**，真实速度 **0**，故障码 **0** |
| 模式确认 | 实际 TPDO 回读 **9**；`6502` 仍为真实零值 |
| 失能后拒绝检查 | 非零 target 被拒绝；兼容未开放的 CST 10、Profile Position 1 请求被拒绝；状态保持失能、零速 |
| CAN | 最终 error-warning、error-passive、bus-off 均为 **0**；最终抓包 41723 帧、错误帧 0 |

角度按设备计数及历史换算折算，未做外部量具校准。下发零速后的使能态反馈存在小幅速度噪声，不登记为调速精度或停止时延验收通过；最终 halt/disable 后真实速度读回为零。只实测 CSV 9 的运动；IP 7 / CSP 8 是限定允许进入真实反馈确认的候选模式，尚未完成这台裸电机的运动验收。200 Hz、整车控制、真实机械制动、停发命令及进程失效停止均未因此通过。

中间测试曾暴露模式切换、停止竞态和健康检查误撤销，相关失败日志、抓包和结果均保留。最后两轮正反向测试及拒绝检查是在最终修改后运行，结果均通过。

结束后主站退出，恢复原心跳、插补周期、模式及全部 PDO 参数。117 项备份对象比较中仅实际位置 `6064` 因运动变化，最终位置 **127489 count**；零偏、软限位及其余参数全部一致，没有写入保存对象。电机保持停止失能。
