# 当前 ROS2 架构与设计决策

更新：2026-11-04。本页描述当前实现；历史 ROS1 方案集中在 `reference/ros1/`。

## 一个控制管理器、两个硬件组件

`robot_hardware` 启动唯一 `controller_manager`。其资源管理器加载私有 CAN 的 `can_driver` 及 CANopen 的 `canopen_ros2_control/RobotSystem`。六轴机械臂由同一个 JTC 执行，不再使用历史双管理器或 4+2 轨迹拆分。CANopen 主站容器在硬件插件内部，维护与运行共享该主站。

`robot_canopen_config` 保留参与生成、交叉校验的 EDS、旧映射快照和 DCF；这些是当前生成器的输入，不能当作已完成测试的产物删除。运行配置由 Lely dcfgen 生成并校验，不依赖 `reference/ros1/` 路径。

## 分组运行与安全条件

arm、base、flippers、gripper 各有运行状态和命令 epoch。关联矩阵根据机械支撑、制动、姿态和载荷条件传播限制；共享通道故障及全局禁止仍可限制多个组。协调器心跳超时撤销许可，恢复不自动进入 Running。

整车 `full_system.launch.py` 默认启用分组策略；底层 `hardware.launch.py` 的空 `group_policy` 保留 ROS2 全局联锁诊断模式。两种模式的操作须按实际启动参数选择，详见 28 和 31。

启动、恢复和控制器切换均清除旧输入。`init` 配置核验，`enable` 到 Armed，`resume` 才建立新的 Running 会话。反馈、输入和关联条件都要满足新鲜度，禁止跨会话重放。设备参数恢复与 ROS2 版本恢复仍需记录，但项目不再要求回退 ROS1。

## 规划、执行和遥控

MoveIt 2 使用 OMPL 与 KDL；`move_group` 的 `allow_trajectory_execution=false`。`arm_goal_executor` 提供项目 ExecuteArmGoal，统一检查运行许可、反馈、控制器及并发状态，再向六轴 JTC 发送轨迹。取消、halt 和失败均要结束旧目标。

Servo 经 `servo_gate` 和独立运行会话输出，与 JTC 互斥。键盘、手柄、Qt 界面及上位机调用项目运行入口，失焦、断流或会话切换清空目标。履带的 Ruckig 平滑层向标准 Twist 控制器发送指令，几何参数以硬件包为准；夹爪最终使用 m/s 指令与受限 CSP 积分。

## 模型与仿真

`car_urdf/urdf/robot.urdf.xacro` 是活动运动学模型；硬件组件、接口和后端参数由 `robot_hardware/urdf/robot.urdf.xacro` 组合。`model_joint_states` 只转发有限位置并保留时间戳供 TF 显示。硬件周期直接检查后端反馈及新鲜度并更新安全许可，上层执行和就绪检查使用原始 `/joint_states`；未配置关节不以伪造零位掩盖无效反馈。

Fortress 复用同一个控制管理器和分组运行逻辑；真实动力学反馈、RGB、深度、IMU 和仿真时钟参与集成测试。`gui:=false` 不取消软件渲染的显示服务要求。

实机、Mock 与 Fortress 入口择一使用：前两者由 `hardware.launch.py` 启动控制管理器，仿真由 Gazebo 插件持有唯一管理器并以 `start_controller_manager:=false` 复用硬件包的运行协调器和控制器加载入口。

## 外围与标定集成

整车 `full_system.launch.py` 默认开启主控制和 MoveIt，外围通过 `enable_cameras/enable_vision/enable_host/enable_co2/enable_thermal` 独立启用，均默认关闭。Servo 与界面也需显式开启；相机与视觉开关互相独立，启用视觉不自动启动相机。

`vision_pkg/vision.launch.py` 默认启动前后视图节点，物体位姿、全景与 H265 分别由其 `enable_object_pose/enable_panorama/enable_h265` 参数启用，默认关闭。这些细分开关目前未由整车入口转发，需要时使用视觉包的独立入口配置；空 `model_path` 不代表已加载 YOLO 权重。

`eye_in_hand` 的标定入口启动 ArUco、上游 `handeye_server` 和 rqt 界面；自动采样通过项目 `/arm_control/execute_goal` Action 走点，再调用上游采样、求解与保存服务。上游通用运动辅助节点不在项目启动链中。标定与保存外参的发布入口分开运行，避免同一 TF 由两个节点同时发布。

## 依赖、插件退出与验收

6 个活动子模块由父仓库 gitlink 锁定。仅 `can_driver`、`ros2_canopen` 作为项目自主维护的控制后端；`realsense-ros`、`OrbbecSDK_ROS2`、`aruco_ros`、`easy_handeye2` 主要作为第三方依赖使用，优先采用上游原版，尽量不修改。项目适配优先在项目包中完成；确有当前功能阻塞且无法通过适配或上游版本解决时，再考虑最小依赖补丁并记录必要性。具体边界见 [系统架构](06_项目架构图与数据流向图.md#子仓库职责与维护边界)，版本发布遵循 [子模块工作流](git_submodule_workflow.md)。

Humble 插件退出修复仅保留相关动态库代码映射到进程结束；标准 JTC/JointStateBroadcaster 的算法与对象析构继续执行。详见 [全量实施记录](archive/34_ROS2全量软件集成与验收.md)。

回归源码持续保留，批次日志与 evidence 可按需在源码树外重新生成。软件验收与真实设备验收分别登记，当前待办见 [实施计划](25_ROS1迁移ROS2实施计划.md)。
