# DM-J10010L-2EC V1.1 说明书核对与 MIT 适配

依据用户提供的 [DM-J10010L-2EC减速电机说明书V1.1](../can_driver/docs/DM-J10010L-2EC减速电机说明书V1.1.md)，版本日期 2026-03-30。用户已确认供电和接线；阶段性暂停后，用户调整120Ω电阻并授权重试，已完成速度和MIT往返实测，见[实机记录48](48_DM单电机实机验证记录.md)。

## 说明书与当前通信问题

| 核对项 | 说明书 | 代码/实测结论 |
| --- | --- | --- |
| CAN 格式 | 标准 CAN，默认 1 Mbit/s | 当前标准帧、1 Mbit/s 与默认值一致；实际值可被改写，未读回确认 |
| 只读查询 | ID 0x7FF，CANID_L/H、0x33、RID、任意四字节；小端返回 | 前述探测寄存器 10 的格式一致，不需要先使能 |
| 反馈路由 | 参数及状态反馈 ID 均为 MST_ID，默认 0 | 原履带配置节点 7→反馈 8、5→反馈 6；寄存器探测接收全部标准 ID，没有按这些反馈 ID 过滤 |
| 速度模式 | CTRL_MODE(十进制10)=3；ID=0x200+ESC_ID，4 字节小端 float32 rad/s | 与 ROS1 历史协议及当前速度后端一致 |
| MIT 模式 | CTRL_MODE=1；ID=ESC_ID；P16、V12、Kp12、Kd12、T12 | 历史后端没有实现，本轮补齐逻辑 position→MIT 映射，不发送 0x100+ID 的位置速度帧 |
| 反馈量程 | 寄存器 21/22/23，float，可配置 | 不应跨型号套用固定值；上轮已改为只读实际量程 |
| 模式切换 | 清零命令；建议先读 0x50 精确位置，尽量零速切换 | MIT 前读取 0x50；已知使能时禁止跨模式切换；使能先发送零增益、中性 MIT 帧，位置目标由上层渐变提供 |
| 位置增益 | Kp范围0–500，Kd范围0–5；控制位置时 Kd 不能为0 | MIT 要求显式正增益，且量化后非零；不自动整定或写入电机 PID 参数 |
| 电阻开关 | 4号为 CAN 120Ω；3号为485 120Ω | 这是型号相关核对点，不代表已确认该开关有误 |
| 波特率 | 寄存器35，编码0/1/2/3/4对应125k/200k/250k/500k/1M | 只改主机速率不能修改电机实际值；实机探测速率尚未运行 |
| 串口 | UART@921600bps，独立调参接口 | 不可把921600当CAN波特率，或把UART/485端子当CAN端子 |
| 速度环 | 阻尼系数寄存器31，float；推荐4.0 | 非零阻尼影响速度响应，但不能解释 CAN 链路错误；未擅自修改 |
| 通讯丢失防护 | 期限内无CAN指令则退出使能；寄存器9 TIMEOUT | 电机实际超时配置未读回，不能登记失联自动停止通过 |

现有证据只能确定：在主机1 Mbit/s下，对历史节点5、7和默认节点1进行少量只读查询后没有有效DM应答，接口从ERROR-ACTIVE变为ERROR-PASSIVE。不能仅凭此判定电机、接线、驱动或固件具体哪一项损坏。节点号、Master ID、控制模式或位置增益不匹配可能导致应用层无应答/无运动，但不能单独解释CAN控制器链路错误。

## reference 与历史协议来源

`reference/ros1/can_driver` 保留 ROS1 包装层、配置解析、生命周期及烟测，没有单独保留 `src/DamiaoCan.cpp`；协议源码从当前子仓库历史提交核对：`56b16da`（首版速度后端）、`2444de4`（配置Master ID）、`003418d`（固定反馈量程）。历史同样使用0x7FF模式写入、0x200+ID速度帧、4位状态及节点号解码；没有发现当前速度帧的字节序或ID偏移相对历史发生变化。

迁移差异包括：ROS1默认定点SI比例在最初ROS2解析器中遗漏、ROS1原有低字节节点0–15限制遗漏；现已修复。当前还保留严格寄存器读回、真实反馈有效性/新鲜度和超时停车；不回退为“无应答也通过初始化”。

## 新增 MIT 软件路径

`protocol: DM`、`control_mode: position` 对应 MIT，需配置 `dm_mit_kp`、`dm_mit_kd`，定点SI比例仍为0.0001。增益允许的最小非零值分别为500/4095、5/4095，最大值分别为500、5。配置示例增益5、0.5仅用于说明格式，未对该实机调参验证。

MIT position发送V_des=0、T_ff=0和位置目标，不采用电机内置位置速度模式。上层需要提供平滑目标并检查实际速度；MIT自身没有由这两个增益构成的硬速度/扭矩限制。使能和停止使用Kp=Kd=0的中性帧，避免突然拉向零位置；中性帧释放驱动力，不等于制动或位置保持，停止验收必须检查真实速度并失能。定点量化使零速度/零力矩存在半LSB左右的误差。

keepalive按模式重发最后帧；超时停止会把MIT缓存换成中性帧，不继续重发旧位置。不同模式的使能/失能/清故障帧使用对应模式CAN ID。CSP仍不支持。

说明书同时列出80(p_m，电机位置)、81(xout，输出轴位置)及10:1减速比。不能据名称直接给现有SI反馈额外乘除10；实机恢复后应读回并核对两项、反馈角度和实际输出轴位移，再验收90°往返。未改零点、限位、保存参数或电机波特率。

## 后续实机工作

待用户恢复实机探测后，先运行 [只读波特率探测](../tools/probe_dm_can.py)，记录实际速率、节点、Master ID及CAN错误；该脚本只调整主机接口，不写电机参数。再备份寄存器7/8/9/10/21/22/23/31/35/80/81等实际参数，确认失能、反馈新鲜、速度接近零。之后才能执行±1 rad/s及MIT正转90°、反转90°回起点。这些前置工作随后已完成，并执行了速度与MIT往返；实测数值及边界见记录48。


实机过程中新增两项修复：配置寄存器应答期限由100 ms改为500 ms（仍要求实际应答，不无限重试）；模式确认后发送中性帧并设置Hold intent，解决失能电机沉默且None intent不安排刷新、无法在使能前取得首帧真实反馈的问题。启停反馈/控制帧发送完成期限仍为100 ms。全部运动结束后原寄存器对比仅80实际位置变化；初始与最终模式均为MIT1。
