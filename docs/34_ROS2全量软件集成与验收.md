# ROS2 全量软件集成与验收

> 本文全量通过结论记录整理前批次；当前目录和本次复测的限制见 [工作区整理说明 35](35_ROS2工作区整理说明.md)。

日期：2026-10-26。承接计划 25 和主控制链记录 33。现有工作树中的上层、仿真和外围实现已纳入同一 ROS2 构建，本轮继续补齐视频入口、标定保存／重启与仿真暂停验收，并修复退出和测试隔离问题。真实设备验收、整车交付与匹配版本发布仍未完成。

## 当前实现与本轮增量

- 正式软件集合为 37 个 ROS2 包，`robot_full_system` 汇总上层、Fortress、相机、视觉、标定、HMI 和传感器依赖。`tools/build_ros2.sh` 只发现选定的 ROS2 包，旧 Catkin 包不进入构建。
- 复用工作树已有的 Servo 门控、JTC／Servo 互斥、腕部 Trigger 服务、手柄／键盘和三个原生 Qt 界面。目标执行、腕部及 HMI 调用最终走项目执行／运行态入口；界面失焦、运行会话改变或输入过期会清除按键目标。
- 复用已有的 ROS2 视觉、H265 编解码、CO₂、热成像和自动采样客户端。模型权重缺失时，开启 YOLO 的服务明确失败，不能把未运行检测算作已验证。
- 补齐安装目录可用的 `host_bridge/video_stack.launch.py`，组合 TCP/JSON 主机桥、视频管理 IPC、ROS2 图像转 RTSP 节点，以及可选 MediaMTX。视频管理器为普通 Python/TCP 进程，使用 `ExecuteProcess` 保留其 argparse 合同。配置必须显式提供。
- `video_stack.sh` 删除 ROS1 master 检查，改为核对 ROS2 环境与已安装的 `host_bridge`；先验证环境和配置再启动进程。脚本与 MediaMTX 启动器已安装，MediaMTX 的端口设置通过 `MTX_RTSPADDRESS` 传入。
- 手眼标定回归扩展为：原生 rqt → 同步合成 TF 采样 → 样本不足拒绝求解／保存 → 8 个已知位姿求解 → 外参矩阵误差校验 → `.calib` 保存 → 两个新发布进程分别读取并发布静态 TF。所有测试标定文件写入临时目录，不覆盖操作者的 `~/.ros2` 数据。
- Fortress 使用物理关节反馈及同一个 controller_manager，保留分组安全门控。扩展验收检查 RGB／米制深度／IMU、CameraInfo 内参及 optical frame、`/clock` 暂停，并确认暂停期间接收的底盘命令过期后不会在恢复时启动运动。测试分别隔离 ROS domain 与 Ignition partition，结束时清理本次进程组，避免连接到已有仿真。
- 全量回归发现 Humble `controller_manager` 退出时仍可能在 executor 析构中访问已卸载插件的回调控制块。本轮给标准 JTC 和 JointStateBroadcaster 增加仅保留动态库代码映射的派生入口，复用项目既有 `retainPluginCode()`；上游控制算法、Action、状态接口和正常对象析构继续保留。插件名改为 `robot_hardware/RetainedJointTrajectoryController` 与 `robot_hardware/RetainedJointStateBroadcaster`，控制器实例名及话题不变。代价是这些动态库保持映射到进程退出。
- 修正 `ros2_canopen/canopen_base_driver` 原单元测试泄漏 Node／驱动的问题，显式关闭上下文、等待 spinner 并释放资源，避免测试断言通过后在 DDS 全局退出时崩溃。该补丁仍在子模块工作树，发布时须一并提交与锁定。

## 构建与运行

在仓库 `src` 目录执行：

```bash
# 首次准备依赖；安装系统依赖需要管理员权限。
bash tools/install_ros2_dependencies.sh --dry-run
bash tools/install_ros2_dependencies.sh
bash tools/prepare_camera_sdk.sh

# 完整软件集合；省略 full 时只构建主控制链。
bash tools/build_ros2.sh /tmp/robot24-ros2 full
source /tmp/robot24-ros2-install/setup.bash
bash tools/validate_ros2.sh /tmp/robot24-ros2 full
```

全量验收需要本机回环 DDS/TCP。Fortress 的软件渲染仍需要可用 X display；`gui:=false` 关闭 Gazebo 客户端窗口，不等于渲染器不需要显示服务。测试没有因为缺失渲染条件而跳过仿真。

```bash
# mock + Servo + 原生遥控界面；运动仍需显式 init/enable/resume。
ros2 launch robot_bringup full_system_mock.launch.py enable_servo:=true ui:=keyboard

# Fortress 物理仿真；同样保留显式运行态操作。
ros2 launch robot_simulation full_system_simulate.launch.py gui:=false

# 实机外围按需启用；设备绑定必须使用现场序列号。
ros2 launch robot_bringup full_system.launch.py \
  enable_cameras:=true behind_camera_type:=realsense enable_paw:=true \
  behind_serial:=BACK_SERIAL paw_serial:=PAW_SERIAL

# 摄像机源配置须由现场确认；已有外部 MediaMTX 时使用默认 false。
ros2 launch host_bridge video_stack.launch.py \
  video_config:=/absolute/path/video_sources.yaml start_mediamtx:=false

# 先按实际打印 marker 确认 ID 和边长，不能沿用旧文档的矛盾组合。
ros2 launch eye_in_hand eye_in_hand_calibrate.launch.py marker_id:=ACTUAL_ID marker_size:=0.05
ros2 launch eye_in_hand publish_calibration.launch.py name:=paw_d405_handeye
```

标定与发布入口不得同时运行两个外参发布者。`eye_in_hand/config/auto_poses_ros2.yaml` 保持 `commissioned: false`；必须核对实际无碰撞采样点后，才可交给 `ros2 run eye_in_hand auto_sample.py --ros-args -p config_path:=/absolute/path/commissioned.yaml`。
