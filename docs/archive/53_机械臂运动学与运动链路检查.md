# 机械臂运动学与运动链路检查

日期：2026-11-17。检查当前 ROS2 活动代码，未连接 CAN 或驱动实物。以下正逆解检查验证软件模型内部一致性，不能替代实机零位、方向、连杆尺寸、TCP 标定和带载运动验收。首次检查没有修改运行代码、限位或标定；下文基线问题的后续修复见末尾。

## 已完成的离线检查

- 机械臂六轴顺序为 shoulder_yaw、shoulder_pitch、elbow_pitch、wrist_pitch、wrist_yaw、wrist_roll。MoveIt、JTC 和 Servo 的顺序一致。
- `car_urdf` 与 `robot_hardware/urdf/model.urdf.xacro` 六轴的 parent、child、origin、axis、limit 逐项一致。控制器及硬件限位也与这六轴对应。
- 肩部两轴由 CANopen 后端控制，其余四轴由私有 CAN 后端控制；同一个六轴 JTC 产生周期位置目标。私有驱动把 65536 count/rev 换算为 2π/65536 rad/count，肘俯仰和腕偏航的方向反转同时用于指令/反馈转换，未发现此处单位或顺序错配。实物方向仍需验证。
- Servo 发布关节速度，`TimedVelocityController` 在 position 接口上积分速度，停止时发布的六个零是速度零；未发现“把速度直接当绝对位置”的错误。
- 使用实际 MoveIt RobotModel、KDL 插件和 FCL，加载已安装的全部碰撞网格检查 5 个命名姿态，均满足六轴限位，按当前 SRDF 碰撞过滤表未发现自碰撞。
- mt19937(42) 生成 100 个限位内关节样本，先正解，再对每轴加 ±0.05 rad 扰动作为逆解初值，使用当前 0.05 s 逆解时限。99 个样本成功；成功样本最大位置误差 9.21175e-6 m（0.009212 mm）、最大旋转误差 9.19588e-6 rad。第 98 个样本失败，同一初值增加到 0.5 s 仍失败。不能据此宣称全工作空间都能稳定逆解；KDL 的局部收敛及初值依赖仍存在。此采样未要求目标无碰撞，不代表可执行轨迹通过率。
- 私有驱动 5 个 CTest 入口通过：意优协议、CSP、限位、分组系统、命令换算。首次运行受沙箱 DDS/日志写权限影响，改用 /tmp 日志和本机 DDS 权限后通过；没有把环境失败归为电机故障。
- CANopen 驱动 5 个 CTest 入口和 ExecuteArmGoal 接口契约测试通过。CANopen 首次运行的组件索引失败，在 source 完整安装依赖后复跑通过。

## 发现及处理优先级

### 1. 无关关节 NaN 会阻止机械臂执行

`arm_control/src/arm_goal_executor.cpp` 的 `/joint_states` 回调先遍历并要求消息内每个位置均有限，再检查是否包含六个机械臂关节。其他组的设备离线时，硬件按设计返回 NaN，因此即使机械臂六轴反馈健康且组状态仍为 Running，执行器也不再更新 `joints_at_`；300 ms 后 ready 失败，新目标会被拒绝，正在运行的目标也可能被取消。

建议仅验证、保存机械臂六轴的唯一且有限反馈，不因无关组的 NaN 拒绝机械臂数据；同时保留机械臂自身反馈超时检查。

### 2. 规划后派发前缺少起点一致性复核

执行器先调用 `setStartStateToCurrentState()` 和 `plan()`，之后直接 `trajectory_->async_send_goal()`；`ready(token)` 仅复核组许可、反馈时效、控制器状态和会话，没有把实测关节与计划起点比较。MoveIt 的 `allowed_start_tolerance: 0.01` 配在执行管理器上，而此路径直接发送 JTC action，没有经过该管理器。

若规划期间同一 JTC 被其他合法入口移动，且 arm 会话没有变化，旧计划仍可能被发送；控制器的路径误差约束不能替代发送前对规划起点和碰撞路径前提的检查。该项为静态代码确认的缺失，本轮未注入并发轨迹复现实际跳变。

建议在派发前按关节名比较实际位置与 `plan.start_state_`，超差则失败或重新规划，同时复核实际速度，避免从运动中的状态开始旧轨迹。

### 3. zero 为奇异姿态，home 接近奇异区

使用 TCP 雅可比的奇异值计算条件数（与当前模型及坐标有关）：

| 姿态 | TCP 位置 / m（base_link） | 最大/最小奇异值之比 |
| --- | --- | --- |
| zero | (0.120334, 0.003000, 1.412538) | 约 3.06e20，数值秩亏 |
| home | (0.315746, -0.022810, 0.369349) | 约 44.53 |
| ready | (0.558243, 0.003000, 0.457564) | 约 8.76 |
| ReadyToCatch | (0.644478, 0.003000, 0.372184) | 约 6.76 |
| ReadyToScan | (0.532809, 0.003000, 0.567816) | 约 10.21 |

当前 Servo 减速阈值为 17、硬停止阈值为 30，并配置离开奇异区的阈值倍率。因此 zero/home 附近的部分笛卡尔指令可能触发减速或停止，不能把这种现象直接判为 CAN 或电机异常。关节空间到达命名姿态与从该姿态进行笛卡尔遥控是两个不同检查项。

建议使用已验证可达且无碰撞的非奇异姿态作为 Servo 起点，保留奇异性保护，不直接提高保护阈值掩盖问题。

### 4. 末端相机没有碰撞几何体

`car_urdf/urdf/robot.urdf.xacro` 的 `catch_camera` 只有 visual 和 inertial，没有 collision，MoveIt 加载时也明确警告碰撞几何为空。规划和 Servo 无法检测相机外壳与机器人或场景的接触。上面的“命名姿态无自碰撞”只对现有碰撞模型及禁碰表成立。

建议按实测包络补充相机碰撞体，再重新验证命名姿态和常用轨迹。`grasp_tcp` 与 `tool0` 当前重合，是否为实际抓取中心需通过现场标定确认。

## 前三项修复（2026-11-17）

第四项末端相机碰撞体按要求暂不处理。本次不修改任何关节位置限位、速度限位、零偏、编码器换算，也不改 zero/home/ready 的历史姿态值。

- 第 1 项：仅接收完整、唯一、有限的本组六轴位置及速度反馈，不合并不同消息的部分关节。无关组 NaN 被忽略；机械臂自身反馈异常立即使就绪失效。move_group 同时改用已有的 `/robot_model/joint_states` 有限反馈流。
- 第 2 项：从实测六轴快照显式构造规划起点。派发前再次核对反馈新鲜度、许可、静止、实际位置限位、规划起点和轨迹首点，超差返回 NOT_READY，不自动发送或重新规划。位置容差使用当前 ROS2 MoveIt 的 0.01 rad（历史 ROS1 trajectory_execution 为 0.05 rad，本次保留更严格的当前值）；静止容差 0.05 rad/s 来自 reference 的混合 JTC。腕滚转按实际多圈位置比较，不做角度回绕。完整轨迹另外核对六轴、时间顺序、有限值、位置和速度上限。
- 第 3 项：新增只读 `/arm_control/check_servo_ready`，在切入 Servo 及 Servo 模式恢复时由运行协调器调用，停止轨迹控制器并重新准备硬件后、激活 Servo 控制器前再次核对。使用与 Servo 同源的阈值和余量参数：条件数必须小于 17、距位置限位至少 0.1 rad，并要求反馈新鲜及静止。检查失败保留轨迹模式（切换前失败时）或关闭运行许可（切换中/恢复失败时）。服务不可用时不绕过检查。
- 新增显式 `/arm_control/prepare_servo` Trigger，经 ExecuteArmGoal 规划到 reference 已有的 ready。它只准备姿态，不自动切换模式；模式切换也不隐式触发准备运动。调用成功后，再请求 `/arm_control/set_servo_mode`。zero 的数学奇异性不会因软件修改消失，保持其校零/关节姿态语义；home 肩俯仰为 -0.877 rad、下限 -0.960 rad，余量仅 0.083 rad，亦不适合直接进入 Servo。
