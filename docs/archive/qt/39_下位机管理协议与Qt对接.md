# 下位机管理协议 v1 / Qt 对接

> 2026-11-08 归档：本页保存 Qt 对接阶段的协议、要求或验证快照；归档不代表 Qt 联调、实机验收或发布已完成。当前 ROS2 缺口统一见 [清单 36](../../36_ROS2迁移剩余事项清单.md)，运行部署见 [robot_manager](../../../robot_manager/README.md)。本文历史命令中的源码路径仍相对仓库根目录。

> 2026-11-08 后续增量：当前控制端点为v2，旧v1仅只读与急停；本页下方控制v1兼容及验证记录属于先前基线，不能当成本轮结果。以[控制v2契约40](40_控制v2与P0交接.md)、[配置事务41](41_配置维护事务与Qt对接.md)、[本轮验证与部署42](42_P0配置事务交付与验证.md)为准。管理请求version仍为1，配置能力需显式部署开启。

独立下位机工作区实现，管理服务不导入 ROS。部署前协议固定如下。

- TCP 9091，UTF-8 NDJSON，每行一个对象，最大 65536 字节；每连接串行请求，多连接并行；空闲超时 10 秒。
- `version:1`，`request_id` 为 1–128 字符字符串，`method` 为下列枚举，`params` 为对象。
- 每个请求携带 `token`，部署文件提供随机至少 32 字符共享令牌（0600）；恒时比较。仅在可信隔离机器人网络或 TLS 隧道内使用，原始 TCP 不提供传输加密。默认仅绑定回环；现场绑定地址须部署者明确配置。
- 响应 `{version:1,request_id,ok,result}` 或 `{version:1,request_id,ok:false,error:{code,message,retryable,hint}}`。命令接受 `ok:true` 不代表任务成功。
- 方法：`hello`、`profiles`、`preflight`、`start`、`stop`、`operation`、`snapshot`、`logs`。
- start/preflight 参数为字符串 `robot_id/profile_id/config_revision`；stop 无参数；operation 可传字符串 operation_id，省略则取当前操作。
- start/stop 异步返回 operation；preflight 同步只读。start/stop 的 request_id 持久幂等，重复 ID 内容不同返回 REQUEST_CONFLICT；并发相同启动返回当前操作，不同档案或停止冲突返回 BUSY。已就绪同档案重复启动复用当前启动操作。失败后用新 request_id 重试，重启结果未知必须先 stop 再 start，不自动重放。
- 操作状态 accepted/running/succeeded/failed/cancelled；本版不提供取消方法。阶段 preflight/launch/health/stop/reconcile/complete，模块结果独立返回。任务时间为 Unix 秒浮点数；超时使用单调时间。
- 软件 stopped/starting/ready/degraded/stopping/failed；runtime 原样返回实际 ROS 运行状态，与软件 ready 独立。未知安全状态为 null，绝不推断许可。
- 日志参数 operation_id、cursor（非负行号，默认0）、limit（1–200，默认100）；返回 lines/next_cursor/expired。每操作日志最多保留前 1 MiB；达到上限后 expired=true，完整子进程日志由部署日志目录保留。操作记录本版不自动删除；运维须停服务后归档，未知 operation 返回 NOT_FOUND，游标超界返回 CURSOR。
- 客户端读取时限建议 15 秒；start/stop 返回后每秒查询；断线重连先 operation 或 snapshot，禁止盲目创建新任务。健康检查单次 12 秒、启动健康预算默认 90 秒，停止按文末阶段预算执行，查询不等待任务。

错误码：AUTH/VERSION/BAD_REQUEST（修正客户端）；PROFILE/REVISION/CONFIG（核对部署配置）；DEVICE/PORT/DEPENDENCY（预检项失败）；BUSY（查询后重试）；REQUEST_CONFLICT（换新 ID）；NOT_FOUND/CURSOR（核对 ID/游标）；HEALTH/TIMEOUT/PROCESS（查看日志后重试）；RECOVERY_REQUIRED/STOP_UNCONFIRMED（先人工确认或受控 stop，不能直接启动）；INTERNAL（检查服务日志）。任务失败错误包含 code/message/retryable/hint，预检失败附 checks。

Qt 顺序：认证 hello → profiles → start → 保存 operation_id → 查询至 succeeded → snapshot 确认 ready/degraded 及所需模块 → 使用 control_endpoint 连接桥接 → hello/capabilities → 匹配 heartbeat_ack → sync_request/system_snapshot → 清空旧输入并显示“软件已就绪，待授权”。保持 init/enable/resume 显式；本管理协议没有运动或解除急停入口。degraded 必须显示故障模块。服务重启后先重新实际健康检查；进行中的旧操作标记 failed/RECOVERY_REQUIRED，不恢复执行。

管理 v1 与控制桥 v1 是不同协议。控制桥 P0 freshness token/session 租约升级尚需双方协商，不能将管理服务交付视为 P0 全部验收完成。

## 字段及状态映射

所有请求的 params 均可省略为空对象。未列出的 method 返回 BAD_REQUEST。标识符和版本区分大小写；revision 是不透明字符串，不做数字比较。

| 方法 | result 类型及字段 |
| --- | --- |
| hello | 对象：protocol_version:int=1，service_version:string，robot_id:string，auth:string，capabilities:string[] |
| profiles | 档案对象数组：profile_id/config_revision/mode/build_version:string；video/video_required:bool；required_modules/optional_modules/devices:string[]；startup_timeout:number(1–180秒)；baseline/video_config:可选绝对路径字符串 |
| preflight | 对象：passed:bool，checks:对象数组（name:string，ok:bool，code:string或null，hint:string） |
| start/stop/operation | 操作对象：operation_id/method/robot_id:string，profile_id/config_revision:string或null，state/phase:string，modules:以模块名为键的对象，error:错误对象或null，retryable:bool，created_at/updated_at:number |
| snapshot | 对象：software_state/build_version:string，profile_id/config_revision/operation_id:string或null，control_endpoint:{host:string,port:int,protocol_version:int}，runtime:原始运行对象或null，safety:对象或null，modules:模块对象映射，observed_at:number或null，recovery_required:bool |
| logs | 对象：lines:string[]，next_cursor:int，expired:bool |

模块结果至少含 ok:bool；重启对账可附 identity_matches:bool，但这不代表模块健康。safety 包含 hardware_initialized/hardware_enabled:bool或null、hardware_components:硬件名到生命周期ID的映射或null、groups:组名到运行状态的映射或null、global_inhibit:bool或null、emergency:{active:bool,source:string}或null。未知字段值为 null 时，Qt 显示“未知”，禁用依赖该许可的操作。软件 ready 只表示软件可服务；硬件 inactive/active 才表示已初始化，active 表示使能，组 Running 和安全 guard 才决定可运行。不得以管理快照替代实时控制许可。

Qt 显示映射：stopped→未启动，starting→启动中，ready→软件已就绪待授权，degraded→软件降级（列出故障模块），stopping→停止中，failed→失败/需恢复。操作 accepted/running→保持进度查询，succeeded→再取快照，failed→展示错误和建议，cancelled→已取消。可重试仅表示可以排查后使用新请求 ID，不表示应自动重放。

阶段预算：预检最多两次包查询各5秒和配置/已有ROS检查5秒；源码发布清单本地SHA256读取另计；启动健康总预算默认90秒（每次探针最多12秒，允许最后一轮收尾超出总预算至多12秒）；停止 halt最多30秒（探针最多27秒，其中服务发现最多12秒，幂等 halt最多尝试两次），每个进程组退出最多11秒。Qt 轮询不以这些预算自动生成新请求。单个慢连接10秒超时，管理并发连接上限16。


## 控制桥 P0 核查与兼容边界

本次保持控制协议版本1；新增 capabilities `monotonic_watchdog`、`connection_control_owner`、`readonly_monitor`。只读 heartbeat/sync/快照/相机列表不占控制权、不重置输入、不在断开时归零其他控制端。首个有副作用请求的连接获取控制权，其余连接收到 protocol_error/code=2110；控制端断开归零并清空输入。此为连接存续期互斥，不等同完整的可续约租约协议。监控连接无需提交新字段，现有 Qt 单连接流程兼容。

控制 watchdog 改用接收端 monotonic；heartbeat 不刷新输入时间。ROS runtime 新增可选 `input_epochs`，桥接只在组运行状态或真实 generation 变化时重置输入，不再因 operations 进度变化反复重置。管理连接本身不创建控制会话，健康探测只用桥接只读消息。ROS launch 新增可选 robot_id，管理档案传入同一标识；直接运行旧 CLI 的默认 loopback_robot 保留。

仍需 Qt 双方协商并验收的 P0 项：现有控制 v1 计算 timestamp/TTL 年龄但不据此拒绝输入；序号只在单一受控连接内隔离，尚无显式签发的 session_id/freshness token；慢 ROS service/视频请求仍沿现有同步调用路径，广播仍可能受慢客户端影响。本次没有以删除 TTL 作为修复，也没有宣称现有 v1 满足积压命令防护或慢服务30秒验收。Qt 应核对所需能力，完整 P0 发布前固定新版协商、令牌期限及中立输入再授权规则，再共同执行时钟跳变/积压/半开连接/慢服务测试。管理最小闭环可以脱离这些升级独立验证，但不能据此发布实机运动可靠性验收结论。

日志分页也受64KiB报文预算限制，单页可能少于 limit，始终使用 next_cursor 继续；其他响应超过上限返回 RESPONSE_TOO_LARGE。显式 preflight 用于停止状态的冷启动检查；受管实例已运行时使用 snapshot/operation，重复 start 会复用原操作，不重新拉起。
