# 控制 v2 / 阶段 A 独立交接

> 2026-11-08 归档：本页保存 Qt 对接阶段的协议、要求或验证快照；归档不代表 Qt 联调、实机验收或发布已完成。当前 ROS2 缺口统一见 [清单 36](../../36_ROS2迁移剩余事项清单.md)，运行部署见 [robot_manager](../../../robot_manager/README.md)。本文历史命令中的源码路径仍相对仓库根目录。

构建系列 `robot24-p0-config-2`。本协议为下位机已实现、Qt 待接、双方待确认和共同验收的增量，不能直接作为现场运动发布许可。源码摘要、命令和本轮实际结果见文档42。管理 v1 与本协议独立。

## 入口与迁移

复用 host_bridge TCP9090（部署可改），UTF-8 NDJSON，单帧含换行最多65536字节。JSON 顶层必须为对象。现有 hello/capabilities 的 protocol_version=1 保留，额外公布 control_protocol_version=2、legacy_control_allowed=false 和 control_capabilities。原来的1MiB帧预算收紧为64KiB。管理9091仍是version=1。

| 客户端 | 许可 |
| --- | --- |
| 旧 Qt 控制 v1 | heartbeat、sync_request、system_snapshot_request、camera_list_request 可用；运动/生命周期明确 UPGRADE_REQUIRED |
| 旧监控/管理健康探针 | 保留 v1 只读流程；健康探针另核验 control_v2 和 legacy_readonly |
| 新 Qt 控制 v2 | 连接后3秒内 control_hello；收到并核对所有必需能力，再进行令牌及显式授权流程 |
| v2 monitor | 不签发控制令牌、不续控制租约，不改变序号、边沿和watchdog；可查任务和机器诊断 |

TCP只适用受信任隔离网络或认证隧道；本次没有发明控制端共享口令或传输加密。管理令牌仍仅用于9091，不可误当成9090认证。默认部署桥接绑定回环；现场网络与身份安全另验收。

必需能力完整列表：session_v2、freshness_v2、explicit_authorization、bounded_operations、isolated_output、runtime_permission。缺任意项拒绝协商。hello请求同时包含robot_id（精确匹配服务端）、role（control/monitor）和capabilities数组。每连接只能协商一次，失败/租约过期须重连。服务端签发随机 session_id，绑定连接和机器人，不能跨连接复制。一个控制租约，最多16个连接。控制连接/租约消失立即撤权；监控断线无影响。

成功响应统一为 `{type:"control_result",protocol_version:2,request_id,seq,ok:true,result:{...}}`；拒绝为同一外壳、ok=false、error:{code}。request_id/seq未提供时回null。v1只读响应维持旧格式。

## 字段约束与流程（等效 schema）

所有v2请求必须 type:string、protocol_version:int=2。协商后必须 session_id:string、epoch:string；control_status 特例可携带旧epoch，返回当前epoch供恢复。普通遥测、operations进度不改epoch；ROS groups或input_epochs真正变化生成新的桥接epoch，撤权并清空令牌。epoch是启动随机UUID与真实运行变化的桥接代次，不冒充ROS计数本身。实际ROS状态来自RosOutput缓存的/robot_runtime/state，原始input_epochs可经管理snapshot.runtime读取；control_status提供对应桥接epoch。

| type | 额外字段/约束 | 返回/含义 |
| --- | --- | --- |
| control_hello | robot_id、role、capabilities | session_id、epoch、robot_id、role、build_version、capabilities、authorized=false；control额外获令牌和预算 |
| freshness_request | 无需seq/token；已有未过期租约和正确epoch | freshness_token、valid_for_ms、refresh_ms=100、input_ttl_ms=300、lease_ms=1500、watchdog_ms |
| operator_input | freshness_token、seq、ttl_ms、keyboard/gamepad | staged（仅入最新槽）或neutral；不是设备动作ACK |
| authorize_operations | freshness_token、seq、ttl_ms | 中立快照300ms内，且无急停，显式允许离散操作；不授予运动许可 |
| authorize | 同上 | 中立快照300ms内、无急停且真实runtime许可成立才authorized=true |
| clear_emergency | 同上 | 要求新中立，撤销所有授权；仅清桥接锁存，不解除ROS guard，不自动resume |
| release_control | 同上 | 撤权并归零，后续重连再申请 |
| system_command | 同上加request_id、command、params对象 | accepted操作；operation_id持久化后才入队 |
| camera_stream_request | 同上加request_id、params对象 | 同一有界操作模型 |
| operation_query | operation_id:string；允许monitor | 操作对象，未知ID为RESULT_UNKNOWN；绝不能盲目重放 |
| control_status | session_id（不要求当前epoch） | epoch、counts、motion_permitted、authorized、emergency_active、queue_depth |
| emergency_stop | 可无会话、无令牌、任何协议版本 | 本地绕过普通分发锁立即锁存和归零，独立安全队列请求ROS halt；physical_stop_confirmed=false |

seq为1..2^53-1整数，连接会话内所有新鲜度请求共用严格递增序号（freshness_request/status/query不消耗）。ttl_ms为1..300整数。timestamp_ms可供Qt诊断，服务端不以跨机墙钟作拒收依据。未知type/command拒绝；未知顶层扩展字段忽略，输入域未知键/轴/按钮拒绝。keyboard是对象，pressed_keys为小写字符串数组，允许w/a/s/d/u/o/q/e/k/i/j/l/f/h/y；数字/模式/服务边沿禁止混在连续快照。gamepad.connected为bool，axes仅left_x/left_y/right_x/right_y/lt/rt且数值有限、范围[-1,1]，buttons仅lb/rb/l1/r1/l2/r2/dpad_up/dpad_down/triangle/cross/x/square/b/circle/y/a且值为bool。不接受NaN/Infinity。中立要求无键、轴在死区内、无按钮；断开的手柄也必须清空值。

system_command仅init/enable/disable/halt/resume/recover/shutdown/set_control_mode/request_arm_named_targets/move_arm_named_target；原有service handler复用。params沿既有命令约束校验，非法业务参数可能接受后执行失败。不能通过任意服务名发起调用。move_arm_named_target另需运动授权和runtime许可。连续输入路径不再隐式调用flipper profile或模式切换服务；Qt须显式使用离散操作/既有runtime配置，不能靠首个输入自动改设备profile。

## 新鲜度、时限与安全

令牌签发时间保存在服务端本地monotonic表，随机值绑定会话及当前epoch。每100ms主动freshness_request；3枚左右token重叠，单枚有效300ms。重复刷新不足100ms复用原token，valid_for_ms为剩余期限。接收和实际输出都检查 `now < issued + ttl_ms`。因采样发生在签发之后，该期限保守限制整个排队输入年龄，不会将刚收到旧输入当成新鲜。客户端必须在收到新令牌后重新采样，禁止为积压帧替换token。令牌耗尽：停止发送旧快照，获取新token、清空队列、重新采样；撤权后中立→显式重新授权。heartbeat仍1秒可用于链路诊断，不能当作100ms令牌更新通道，也不续输入watchdog。

100Hz控制tick目标；300ms总token预算建议划分：刷新100ms、网络往返100ms、Qt及服务器排队/调度100ms。watchdog为min(配置,500ms)，有效输出停止后不因heartbeat或拒收输入续期；租约1500ms，仅freshness_request续约。runtime状态年龄必须小于1秒。上述是保守配置和本地测试目标，不是实测现场网络上界，部署前须采集Qt RTT/排队P99并共同确认。

runtime许可依赖真实ROS四组全部Running，diagnostics.readable=true、global_inhibit=false、owner_fresh=true，各guard组state=2/ready=true/blockers=[]。ready是共享安全域根据硬件和控制器证据产生的权威许可；不使用管理software ready、默认硬件值或ACK。未知/缺失/过期一律撤权，初始dry-run不会伪造许可；fixture专门显式注入模拟许可。当前策略保守要求四组许可，尚未协商部分组驾驶。

归零每10ms在未授权状态重复发布；断线、watchdog、epoch、急停、许可丢失均撤权；曾有运动授权或正在执行命名运动时，同时经独立安全队列请求ROS halt，覆盖轨迹动作不能由速度零值停止的边界。control_status.safety_halt提供RPC状态，仍不等同物理停止确认。急停锁存写入独立emergency.json持久文件，跨重连/桥接重启保持；清除需显式请求，不由ready/通信恢复触发。锁存归零不等待普通任务，但持久化fsync有磁盘延迟；不提供Python调度的硬实时承诺。ROS共享guard、owner watchdog、控制器与硬件停止保障必须保留，不能以桥接归零代替硬件签收。

## 异步任务与资源边界

单普通worker、16项等待队列；急停有独立单worker和1项合并等待槽。ROS/action/video调用不持admission锁，操作journal的JSON编码、写盘和fsync也不持该锁；接收线程等待持久接受时，其他连接和watchdog继续运行。持久化后执行前再检查原token期限，慢磁盘不能把过期意图放行。普通操作执行前重验session/lease、operations_authorized、epoch、原token截止时间及急停，过期队列项失败且不产生副作用。拒绝QUEUE_FULL/CACHE_FULL不执行。允许任务只接受300ms内立即开始；慢任务后方操作多数会EXPIRED_IN_QUEUE，Qt必须查询后以新明确意图重新请求。

request_id为1..128字符，机器人范围内持久幂等，绑定type/command/params规范JSON摘要。相同内容重试查询原operation，不要求重试token仍新鲜；不同内容REQUEST_CONFLICT。持久journal最多512项，至少保留24h，实际不自动淘汰，墙钟跳变不会清理幂等记录；空间满返回CACHE_FULL，需停机显式归档。需私有且持久的 --control-state-dir，默认/tmp/robot24-control-<port>仅开发，机器重启清理/tmp会丢失幂等记录，部署必须改成持久目录。目录flock防双实例。

操作对象包含operation_id/request_id/robot_id/epoch字符串、command字符串或null、state字符串枚举、created_at Unix秒数、authorization_generation整数、invalidated布尔、error字符串或null、result数组或null，可选late_backend_results数组。状态：accepted/running/succeeded/failed/result_unknown。result是既有业务响应数组，包含服务端业务失败；超时/异常/结果过大标result_unknown。无取消方法，超时不意味着ROS或物理动作已停止。ROS Trigger发现预算2秒、单次响应等待30秒；MoveIt action服务发现2秒、goal ACK 5秒、结果120秒，超时仅尝试3秒取消回包，仍保留结果未知。video IPC沿部署timeout，工作线程等待不影响控制tick。任务已开始后撤权不能撤回已发送ROS调用，完成对象invalidated=true，Qt仍需显示最终结果、保持运动禁用，并查询runtime。桥接重启将accepted/running改result_unknown/BRIDGE_RESTART，不重放。ROS超时后若future迟到完成，operation.late_backend_results记录success/message/error；这只是底层RPC完成证据，保留result_unknown且不恢复授权，仍需实际runtime/设备对账。

每连接32项发送队列（帧≤64KiB）、1秒排队期限/套接字写超时，满则断开该连接，最多16连接，线程数有界。慢监控不阻塞broadcast或其他连接；同一连接TCP前面已积压字节仍有FIFO限制，急停应有独立连接/硬件通路。状态计数accepted、outputs、revocations及各拒收码在control_status输出，不以日志判定许可。

错误枚举：UPGRADE_REQUIRED、IDENTITY_ROLE、CAPABILITIES、ALREADY_NEGOTIATED、NEGOTIATION_TIMEOUT、OWNER_BUSY、BUSY、SESSION、EPOCH、LEASE、TTL、SEQ、REPLAY、STALE_TOKEN、INPUT_SCHEMA、INPUT_KEYS、NEUTRAL_REQUIRED、NOT_AUTHORIZED、OPERATIONS_NOT_AUTHORIZED、RUNTIME_PERMISSION、EMERGENCY_ACTIVE、METHOD、COMMAND、PARAMS、REQUEST_ID、REQUEST_CONFLICT、QUEUE_FULL、CACHE_FULL、PERSISTENCE、RESULT_UNKNOWN；任务还可EXPIRED_IN_QUEUE、BACKEND_TIMEOUT、BACKEND_REJECTED、BRIDGE_RESTART、底层异常类型。BAD_REQUEST表示字段类型非法。错误不得刷新watchdog。

## Qt精确改动清单

1. RobotTcpClient解析入口新增v2协商与能力核验，旧hello不代表允许控制；控制端点版本从管理snapshot读取，管理客户端保持v1。
2. 保存connection-bound session_id/epoch；100ms独立刷新token，使用本地单调RTT，丢弃旧输入队列，每次token之后重新采样；发送单调递增seq和ttl_ms≤300。
3. 重连先sync/status，清空键/手柄及离散重试缓存；中立→显式authorize_operations完成init/enable/resume等操作，实际runtime允许后再中立→authorize。禁止管理ready自动使能。
4. 拆分连续快照与离散模式/速度/服务操作。本版未提供速度等级在线设置，保留服务端配置默认档；不能把原数字边沿送入v2。
5. 任务ACK只表示接受；保存request_id/operation_id，operation_query轮询。断线同ID同参数查原结果，冲突/未知/invalidated/超时显示明确状态；绝不自动重放enable/init。
6. runtime/令牌/epoch/租约失效清空授权UI，等待新中立与人工意图；status可用旧epoch取当前代次，更新后再请求令牌。租约真正过期须重连。
7. 急停单独发送，不依赖运动租约；清急停不等于ROS guard已释放，单独显示桥接锁存和实际runtime许可。

## 可运行fixture和验证入口

`PYTHONDONTWRITEBYTECODE=1 python3 host_bridge/control_fixture.py` 输出完整请求/响应NDJSON，包含成功、拒收、epoch恢复、任务和超时结果未知。全部是无设备模拟。`python3 -m unittest discover -s host_bridge/tests -v` 包含注入墙钟±24h、100轮恢复及真实30秒阻塞；真实ROS2 mock和部署步骤见文档42。24h长稳和实机归零必须另行签收，短测不得代替。
