## 1. 已实施内容与激活边界

- `robot_safety/config/group_policy_v1.yaml` 冻结 13 个主动轴的四组所有权、五个运动控制器及摆臂互斥关系；单一 CANopen 主站和两个 SystemInterface 保持原拓扑。
- `Domain` 新增轴 ready、组状态/原因/epoch、结构化事件、关联矩阵、带来源和有效期限的三态证据、显式确认及全局禁止。默认未报告轴不是 ready；配置文件也不能将轴预置为 ready。
- 新接口 `permits(group, epoch)` 仅许可具体组；局部 halt/fault/arm 不更改独立健康组 epoch。重新 arm 仍不许可运动；需要明确 run 及新控制器会话。调用者必须在每轴写入前检查本组许可。
- 事件中同时含轴和后端时按轴确定设备范围；只有后端范围事件才覆盖该后端全部轴。机械关联按配置计算传递闭包。
- 相同事件 ID 重复上报不会重建健康会话；同一 ID 改变来源、类别、严重度或原码会被拒绝。事件确认保留 Fault，显式 arm 才能回到 Armed。源仍未 ready 时不能确认停止类事件。
- 缺失、过期、来源不匹配和明确不满足的证据都不能放行依赖组。无故障事件但关联源组尚未准备时，也生成 `unavailable:<group>` 限制。真实故障记录须显式确认；`unavailable` 是根据当前就绪状态计算的限制，不是假造设备故障。
- 许可查询会提交证据到期的故障转换并撤销 epoch。到期后补充新证据不会使旧会话复活。只报告总线恢复不会伪造每轴反馈已恢复。
- JSON 诊断增加 `aggregate_state`、四组状态、轴 ready 原因、实际阻断事件、关联条件及所需证据来源、原码和恢复条件；保留旧字段用于兼容。旧 `state()` 仍表示旧全局路径，不能用它判断新分组许可。
- `Freshness` 提供每反馈通道独立的告警/停止阈值与稳定窗口，使用调用方提供的单调时间。到达停止阈值、无效反馈和硬故障立即关闭许可，不增加漏帧去抖；告警在稳定窗口后清除。启动及停止后的稳定窗口不许可运动。

**迁移保护**：新组接口不会通过旧 `permits(epoch)` 打开实际硬件路径。旧硬件、运行协调器及 mock 仍走原全局联锁；配置标记为 `activation: staged`，尚无运行时 YAML 加载或分组 ROS 服务。新旧模型同时存在于迁移期间；分组配置存在时，未迁移的 `fault()` 或活动组期间的旧 `report(false)` 保守地禁止全部组。不能只加载该配置或只修改 Fault 判断就放开现场运行。

`Domain` 对象布局发生变化，后续整链验证必须重新编译所有使用者，不能用新共享库替换旧二进制进程中的库。本次产物仅安装在 `/tmp/group-install`，未替换现场安装目录。

## 2. 事件合同

| 触发类型 | 默认严重度 | 设备/任务范围 | 停止与恢复合同 |
| --- | --- | --- | --- |
| 非法新请求、参数错误 | Reject | 当前请求 | 拒绝，不撤销无关会话 |
| 速度命令超时 | Warn/控制器本地超时处理 | 对应控制器 | 归零或保持；新命令，不执行整车 recover |
| 控制器运行中非法输出 | GroupStop | 所属组 | 撤销会话，修复源并显式 arm/start |
| 可信期限内延迟/周期抖动 | Warn | 对应反馈通道 | 不突破可信时间上限，稳定窗口撤警 |
| 反馈过期、心跳超时、非预期失能/模式变化 | GroupStop | 轴所属组 + 机械关联 | 立即撤销，可信状态稳定、明确确认、重新 arm/start |
| 未分类 EMCY | GroupStop | 轴所属组 + 机械关联 | 保留原码，诊断后明确确认；没有依据的 known 映射为空 |
| 单条 SDO 失败 | Reject 当前操作；准备失败可 GroupStop | 实际依赖该读回的操作/组 | 不返回缓存成功；有界重试或明确恢复 |
| 保存/回滚不确定 | GroupStop | 目标轴组 + 机械关联 | journal 持久保留，身份确认、restore/读回及显式确认 |
| 共享传输失效 | GroupStop | 该传输全部轴所属组 + 机械关联 | 先撤销全部资源使用者，再恢复共享资源；不重建健康总线 |
| 急停、无法界定范围的危险 | GlobalStop | 全组 | 全局禁止独立锁存；确认全局事件并显式 reset，再分别 arm/start |

`evidence_valid` 记录事件发生时证据是否可信，不代表关联条件已经满足。关联证据必须通过 `condition(name, value, source, valid_until)` 另行提供。时间均为单调纳秒，不使用 ROS 仿真时钟/墙上时间作为新鲜度依据。事件恢复说明是给调用层的合同；引擎只检查源 ready 和显式确认，具体错误的诊断及恢复验证由 P2/P3 接入负责。

## 3. 初始关联矩阵

| 源组 | 故障类别 | 依赖组 | 继续所需条件 | 指定信息来源 | 无/过期证据 |
| --- | --- | --- | --- | --- | --- |
| arm | 全部停止类事件/不可用 | base | arm_secured | commissioned_arm_pose_and_brake | 阻断 |
| flippers | 全部停止类事件/不可用 | base | support_trusted | commissioned_support_state | 阻断 |
| gripper | 全部停止类事件/不可用 | arm | payload_retained | commissioned_payload_state | 阻断，并继续计算 arm → base |

这些来源名是待现场确认的信息通道标识，不是已经存在的传感器。所有初值均为 unknown。离线用例中的 Satisfied 只属于带受控时间和来源的测试输入，不会写入现场配置。单摆臂失效仍停止四摆臂；单履带失效停止双履带；任一肩/肘/腕轴失效停止六轴任务。

## 4. 状态转换表

| 当前组状态 | 操作/事件 | 必要条件 | 后继状态及 epoch |
| --- | --- | --- | --- |
| Stopped/Fault | arm(group) | 所有本组轴 ready、无关联阻断、全局允许、停止类事件已确认 | Armed；新 epoch |
| Armed | run(group) | 就绪/全局/关联条件仍成立 | Running；保持已准备 epoch |
| Running | arm(group) | 不允许隐式重建运行会话 | 拒绝，保持会话 |
| Armed/Running | halt(group) | 无需设备回复才能撤销许可 | Stopped；撤销 epoch |
| 任意 | GroupStop | 按设备、组、后端及关联闭包计算 | 受影响组 Fault；第一次撤销 epoch；重复 Fault 不重复递增 |
| Fault | 反馈变好/证据恢复 | 单独不足以自动恢复 | 仍 Fault；需确认/arm/start |
| Fault | acknowledge(id) | 源 ready，调用层已确认恢复条件 | 保持 Fault；移除该事件阻断，其他事件仍生效 |
| 任意 | GlobalStop | 无 | 全部 Fault，全局禁止锁存 |
| 全局禁止 | resetGlobalStop | 不存在未确认的 GlobalStop 事件 | 只清全局禁止，不自动 arm/run |

Reject/Warn 不更改组 epoch。源组就绪恢复不代表旧轨迹或速度还能继续。旧路径全局 Fault/恢复行为仍由原回归样本保留。

| RuntimeNode::monitor/jog/trajectory/flipper_step | 恰好四控制器、全局 Running；监控错误 converge | 按请求组校验控制器与资源所有权；拒绝非法新目标、局部超时和局部停止 |

## 6. 验收分层与当前结论

模型测试覆盖：独立组启动的必要关联证据、双履带故障范围、跨后端机械臂范围、夹爪与总线范围区别、传递关联、未知/过期证据、重复事件、恢复时再次故障、全局禁止、会话不重放及并发上报。Freshness 测试覆盖阈值边界、硬故障即时停止、告警清除滞回、启动/恢复稳定窗口和不同反馈通道独立阈值。配置测试对照真实两个 URDF 及 controller YAML 检查轴/组/资源，无静默重复键。

模型通过不等于 29 号最低离线矩阵通过。以下验收仍未覆盖，不能打勾：

1. 两个真实插件逐轴初始化/读写与组件 ERROR 隔离、跨后端硬件周期同步停止。
2. 实际 Humble controller_manager 中接口保持、健康 JTC 轨迹与健康底盘持续运行。
3. ROS 服务中的组选取、轴级 enable/recover、共享资源恢复、长操作并发和迟到回复。
4. 摆臂局部切换、按组监控、维护 journal 范围及命令工具。
5. 全部依赖从空前缀构建、发布版本匹配与搬迁验证。
6. 现场制动/支撑/载荷证据、实际电机停止效果与时延。

因此保留原全局策略，未发布三个仓库的新匹配版本。下一实施阶段是 P2，随后依次 P3–P6；不存在“软件已完成只缺实机”的结论。
