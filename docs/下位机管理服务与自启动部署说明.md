# 下位机管理服务与自启动部署说明

更新：2026-11-25。本说明定义去除了 `robot24-portable` 中间运行层后的下位机日常运行、异常自恢复与目标机一键 `systemd` 自启动部署流程。

---

## 一、架构与目录约定

下位机不再维护独立的 `~/robot24-portable` 中间目录，按使用阶段分为两种运行模式（均不硬编码用户名）：

| 阶段 / 模式 | 程序与安装产物 | 运行配置、令牌与档案 | 状态、日志与 ROS 运行时 | 启动入口 |
| --- | --- | --- | --- | --- |
| **开发 / 非最终环境**（当前默认） | `~/ros2_ws_car/install` | `~/.local/share/robot24/`（可设 `ROBOT24_RUNTIME_DIR`） | `~/.local/share/robot24/{state,ros-home,ros-logs}` | `bash ~/ros2_ws_car/src/tools/run_manager.sh` |
| **目标车端一键自启动**（最终环境） | `/opt/robot24/install` + `/opt/robot24/manager` | `/etc/robot24/{manager.json,manager.token,profiles}` | `/var/lib/robot24-manager/` | `systemd` 服务 `robot24-manager.service` |

上位机连接脚本（`~/hostcomputer/scripts/run_linked.sh` 与 `show_manager_connection.py`）按以下优先级自动发现管理配置：
1. `HOSTCOMPUTER_MANAGEMENT_CONFIG` 环境变量（显式指定）
2. `/etc/robot24/manager.json`（目标机已安装 `systemd` 自启时）
3. `${ROBOT24_RUNTIME_DIR:-$HOME/.local/share/robot24}/manager.json`（开发/终端模式）

## 二、当前阶段：保留终端启动与自动准备

在非最终主机上暂不安装系统级 `systemd` 服务，继续使用终端命令启动管理服务：

```bash
# 终端 1：下位机管理服务（内置运行态初始化与崩溃退避自恢复）
bash ~/ros2_ws_car/src/tools/run_manager.sh

# 终端 2：上位机（自动读取 ~/.local/share/robot24/manager.json）
bash ~/hostcomputer/scripts/run_linked.sh
```

`run_manager.sh` 执行逻辑：
1. 调用 [prepare_runtime.py](../tools/prepare_runtime.py) 检查并初始化 `~/.local/share/robot24/`：
   - 已有 `manager.token`、`state/` 与自定义档案保持原样不覆盖（通过 `state/lock` 文件锁避免并发篡改）。
   - 首次运行或新迁移主机自动生成 `0600` 权限的 32+ 字符 `manager.token`、写入指向当前 `~/ros2_ws_car/install` 的 `manager.json`，并从源码基线补齐 `mock.json` / `hardware.json` 及注册基线 YAML。
2. 以受监督模式启动 `robot_manager/manager.py`（默认开启；加 `--no-supervise` 可单次直出运行便于调试）。

## 三、目标下位机：一键自启动部署接口

当软件迁移到最终车端工控机、需要上电即进入可一键启动状态时，通过 [install_autostart.sh](../tools/install_autostart.sh)（封装 [autostart.py](../robot_manager/autostart.py)）完成系统化部署。

### 1. 部署前预览（不改系统，无需 sudo）

```bash
bash ~/ros2_ws_car/src/tools/install_autostart.sh plan
```

检查 `~/ros2_ws_car/install/setup.bash` 与 `robot_manager/manager.py` 是否完整，并输出将安装的 `/opt/robot24`、`/etc/robot24`、`/var/lib/robot24-manager`、`systemd` 单元与 `logrotate` 路径。

### 2. 一键安装系统自启动

```bash
# 仅部署管理服务开机自启
sudo bash ~/ros2_ws_car/src/tools/install_autostart.sh install

# 同时安装 can0/can1（1 Mbps、txqueuelen 1000）udev + systemd 自动配置
sudo bash ~/ros2_ws_car/src/tools/install_autostart.sh install --with-can
```

如需要将开发阶段本地档案与认证令牌直接迁入系统目录，可附加 `--source-runtime ~/.local/share/robot24`；跨主机远程接入可附加 `--advertise-host <下位机可达IP>`（也可后续编辑 `/etc/robot24/manager.json` 中的 `control_endpoint.host` 并重启服务）。

安装动作包含：
1. 校验目标 `/var/lib/robot24-manager/state.json`（及可选源运行目录）中无未停止的受管资源；
2. 将 `install/` 与 `robot_manager/` 实体化复制到 `/opt/robot24/{install,manager}`，并重新生成 `/opt/robot24/install/release.json` SHA256 清单；
3. 生成/迁移 `/etc/robot24/{manager.json,manager.token,profiles/}` 与 `/var/lib/robot24-manager`（`0700`）；
4. 创建系统用户 `robot24`（加入 `dialout`、`video` 组）并赋权；
5. 安装 `/etc/systemd/system/robot24-manager.service` 与 `/etc/logrotate.d/robot24-manager`，执行 `systemctl daemon-reload` 与 `systemctl enable --now robot24-manager.service`。

### 3. 日常运维与卸载

```bash
# 查看服务状态与日志
systemctl status robot24-manager.service
journalctl -u robot24-manager.service -f

# 卸载服务（先通过上位机或 client.py 完成受控 stop，确认无残留受管资源）
sudo bash ~/ros2_ws_car/src/tools/install_autostart.sh uninstall
# 如需连同 /etc/robot24 与 /var/lib/robot24-manager 一并清除，追加 --purge
```

### 四、异常与故障自恢复设计

1. **终端守护退避自恢复与熔断（[run_manager.sh](../tools/run_manager.sh)）**
   - 收到 `SIGINT`/`SIGTERM` 或子进程正常退出（`0`）时，平滑退出不拉起。
   - 若 `manager.py` 异常退出（非 0），将退出码与时间记录至 `supervisor.log`，按 `2s → 4s → 8s → 16s` 指数退避自动重启。
   - 120 秒滑动窗口内连续崩溃达 5 次触发熔断，停止自拉起并提示日志与 `state.json` 路径，防止坏配置/坏状态引起死循环。

2. **Systemd 服务层自恢复（[robot24-manager.service](../robot_manager/systemd/robot24-manager.service)）**
   - 配置 `Restart=on-failure`、`RestartSec=2` 与 `StartLimitIntervalSec=60` / `StartLimitBurst=5`。
   - 使用 `KillMode=process`：`manager` 崩溃重启期间不强杀已有的 ROS 启动进程组，保留进程身份供新启动的 `manager` 进行状态对账与安全停机。

3. **管理服务内部故障对账与跨重启防死锁（[manager.py](../robot_manager/manager.py)）**
   - **运行中进程崩溃**：`monitor()` 检测到必需模块（`core` / `bridge`）失联并将 `software_state` 标为 `failed` 时，若仍有受管 `resources`，立即设置 `recovery_required=true`，使上位机同步解除待命启动并引导先执行“停止系统”。
   - **主机掉电/重启防死锁**：若 `state.json` 中记录了上次系统启动的受管资源，主机重启后新系统可能把相同 PID 分配给无关系统进程。`Backend.stale_previous_boot()` 与 `Backend.stop()` 会核对 `/proc/sys/kernel/random/boot_id`；确认所有残留资源属于旧 `boot_id` 且当前启动无存活 ROS runtime/模块后，允许通过管理 `stop` 清理旧记录，避免陷入 `process identity changed` 或 `STOP_UNCONFIRMED` 死锁。
   - **状态文件损坏保护**：`state.json` 被截断或损坏时释放文件锁并显式抛错退出，绝不静默重置 `resources` 所有权。
   - **安全边界保持不变**：管理服务自恢复只恢复“管理通道与对账能力”，**绝不自动重启硬件电机控制或自动解除急停**；`hardware` 在未经过受控 `halt` 确认前仍保持 `STOP_UNCONFIRMED` 保护。

## 五、离线测试与分段演练

```bash
# 1. 下位机管理单元测试（含运行崩溃恢复、跨重启 boot_id 清理与损坏 state 保护）
PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest discover -s ~/ros2_ws_car/src/robot_manager/tests -v

# 2. 运行态准备与分段自启动测试（使用临时目录，不修改本机系统目录）
PYTHONDONTWRITEBYTECODE=1 python3 -B ~/ros2_ws_car/src/tools/test/test_autostart_and_runtime.py -v

# 3. 手动分段演练安装到临时根目录
python3 -B ~/ros2_ws_car/src/robot_manager/autostart.py install \
  --ws-root ~/ros2_ws_car --root-prefix /tmp/robot24-autostart-stage \
  --source-runtime ~/.local/share/robot24
```
