# 底盘与摆臂简易键盘控制启动说明

更新：2026-11-17。对应当前源码中的 [底盘脚本](../tools/base_keyboard.py) 和 [摆臂脚本](../tools/flipper_keyboard.py)。这两个脚本分别打开一个 Qt 按键窗口，直接控制实机；不会启动 Gazebo，也不通过整车 `robot_group` 协调器。

## 1. 启动前确认

- 两个脚本都固定使用 **`can0`**，不会自动识别接口或电机 ID；`can0` 须已接好对应设备、配置正确的 CAN 波特率并处于 UP 状态。可只读查看：`ip -details -statistics link show can0`。
- **启动会初始化/使能电机，不只是打开界面。** 底盘脚本启动后两轴保持使能、等待按键；摆臂脚本准备各轴后失能待机，按键时再使能对应轴。
- 先退出控制这些电机的整车硬件 launch、其他主站或测试程序。两个键盘脚本共用 `/tmp/robot24-base-keyboard.lock`，**只能择一运行**；这个锁不会阻止其他程序占用总线。
- 使用有图形桌面的终端。按键作用于弹出的控制窗口，点击窗口使其获得焦点后再操作。需要 Python 3、PyQt5；底盘脚本还需要 ROS2 Humble 和当前版本的 `can_driver` 安装环境。
- 摆臂脚本是空载调试工具，按输出端每圈 19857408 counts 换算角度，不设启动位置的相对行程限位，**不读取整车 URDF 的绝对限位**。驱动器自身的限位配置不变。

## 2. 公共终端环境

以下命令从当前工作区源码目录执行；不要在一个终端里依次执行两个启动命令来期待同时打开两组。

```bash
cd /home/fire/ros2_ws_car/src
source /opt/ros/humble/setup.bash
source /home/fire/ros2_ws_car/install/setup.bash
export ROS_LOCALHOST_ONLY=1
export ROS_LOG_DIR=/tmp/robot24-keyboard-roslogs
```

底盘脚本从当前 ROS 环境中查找 `can_driver_node`，无需另外手工启动该节点。可只读核对所用安装位置：

```bash
ros2 pkg prefix can_driver
```

如果该安装目录不存在或缺少当前 `can_driver`，可仅构建它及项目依赖，再用新安装环境替代上述工作区 setup：

```bash
source /opt/ros/humble/setup.bash
colcon --log-base /tmp/robot24-keyboard-log build \
  --base-paths robot_safety can_driver --packages-up-to can_driver \
  --build-base /tmp/robot24-keyboard-build \
  --install-base /tmp/robot24-keyboard-install \
  --cmake-args -DBUILD_TESTING=OFF
source /tmp/robot24-keyboard-install/setup.bash
```

## 3. 底盘双电机：启动和按键

完成公共环境准备后执行：

```bash
python3 tools/base_keyboard.py
```

窗口标题为“底盘键盘控制 — can0”。终端打印 `READY: 双电机已使能，等待用户键盘输入。` 后，在窗口内操作：

| 按键 | 操作 |
| --- | --- |
| 按住 W | 前进 |
| 按住 S | 后退 |
| 按住 A | 左转 |
| 按住 D | 右转 |
| 松键 / 空格 / 窗口失焦 | 发送零速停车 |
| Esc / 关闭窗口 / “停止并退出”按钮 | 停车、失能并关闭驱动 |

脚本将前后与转向输入混合为左右轮速度，组合按键也会归一化，轮轴指令不超过 **0.5 rad/s**。窗口约每 20 ms 更新，驱动配置的连续指令超时为 0.2 s。

| 轴 | Motor ID | Master ID | 方向系数 |
| --- | --- | --- | --- |
| 左轮 `left_front_wheel_joint` | 7（0x07） | 8（0x08） | +1 |
| 右轮 `right_front_wheel_joint` | 5（0x05） | 6（0x06） | -1 |

日志目录由终端打印，形如 `/tmp/robot24-base-keyboard-xxxx/`，包含本次生成的 `config.yaml` 和 `driver.log`。

## 4. 四摆臂：启动和按键

先完整退出底盘窗口，确认停止后执行：

```bash
python3 tools/flipper_keyboard.py
```

窗口标题为“四摆臂空载连续控制 — can0”。节点的角色按脚本固定编号定义：

| 节点 ID | 脚本中的摆臂名称 | 正向按键 | 反向按键 |
| --- | --- | --- | --- |
| 1 | 左前 | Y | H |
| 2 | 右前 | U | J |
| 3 | 左后 | I | K |
| 4 | 右后 | O | L |

- 按住按键连续运动，**每次只能操作一个轴**；同时按多个运动键时停止提交运动意图。
- 松键、空格或窗口失焦：按配置减速停车，确认稳定后失能；并非瞬时机械停止。
- Esc 或关闭窗口：停车、失能并退出。
- 请求速度约 **5°/s**，加减速度约 **4°/s²**，**不设启动位置的相对行程限位**；持续按住会持续运动，松键后停车。
- 启动要求节点初始失能，且 `0x6061` 为 **Profile Position 模式 1**；脚本不会自动把整车 CSV/IP 模式切成模式 1。模式不符时停止，按设备已确认的操作流程处理。
- 启动时会修改位置曲线相关 RAM 参数并保存原值；退出时尝试恢复。不写零点、绝对限位或保存对象，恢复异常会记入日志。

日志目录形如 `/tmp/flipper-keyboard-xxxx/`，事件在 `events.jsonl`，控制线程结束后保存 `samples.json`。

本说明的普通启动命令不带 `--self-test`，该参数会执行自动运动，不能当作查看帮助或只读检测使用。取消行程限位后，`--boundary-test` 已停用，传入时直接退出。

## 5. 常见启动问题

| 现象 | 检查方式 |
| --- | --- |
| 提示锁被占用 / `BlockingIOError` | 先正常退出另一个底盘或摆臂键盘程序；不要通过删除锁文件来绕开正在运行的进程 |
| `can0` 不存在、未 UP 或无反馈 | 只读检查接口和实际接线、波特率、节点 ID；脚本没有接口选择参数 |
| 找不到 `rclpy`、`can_driver` 或消息字段不匹配 | 重新 source ROS2 和与当前源码匹配的安装环境；底盘程序还需要当前驱动生成的消息接口 |
| 找不到 `PyQt5` 或无法连接显示服务 | 检查 Python 图形依赖及当前桌面/显示环境 |
| 摆臂提示“需要原位置模式1” | 当前驱动模式不符合该空载工具的前提，不要将它与整车主站同时运行 |
| 按键无反应 | 点击控制窗口；确认窗口反馈正常；摆臂一次只按一个运动键 |
